ADR-026 — 理解度チェックを4択化し完了条件から誤答を外す

Status​

Accepted（2026-07-29）

Context​

ADR-025 は AI レビューを3観点の完了判定機構に格上げし、観点3（理解度チェック）を「1回目は質問の提示、2回目に回答を評価する」2ラウンド方式と定めた。この機構を PR #52 で実運用したところ、次の問題が観測された。

出題内容が変更の主目的から外れた細部に寄る。 ルーブリックの規定（根拠を file:line で示す／問う対象3カテゴリのうち1つが「境界値」／難易度の上限が「リポジトリ外の知識を要求しない」だけ）が組み合わさり、問いの括弧内で答えを名指ししてしまい、その代償としてより細かい論点へ降りる出題になっていた。この点は出題規律の明文化で解消済みである（PR #67）。

学習ループが閉じていない。 観点3 は正解も解説も出さないため、誤答した学習者が正解に到達する経路がない。チュートリアルリポジトリでありながら、間違いを指摘して何が正しいかを教えない状態だった。

自由記述4問の回答コストが高い。 PR #52 のラウンド1は未回答（判定不能）のまま停止し、10日近く進まなかった。

誤答が恒久的な未完了を生む。 ADR-025 の完了条件は3観点すべて OK である。観点3 の OK 条件は「全問に回答があり、いずれも差分と矛盾しない」ため、1問でも誤答すると未完了が確定する。誤答は既に起きた事実であり、修正して解消できる種類のものではないため、学習者はタスクを完了できない。

Decision​

観点3 の出題様式と判定方法を次のとおり改める。ADR-025 が定めた観点1・観点2・CI green の扱い、および required status check を導入しない方針は変更しない。

  • 出題は3〜5問の4択とし、回答に「選んだ理由を一文」を添えさせる。問う対象は5カテゴリ（振る舞い／因果関係／契約／エッジケース／トレードオフ）から1問1カテゴリで選ぶ。選択肢設計の規律（誤答は実際にありうる誤解を反映させる／長さ・文法・具体性・確信度のトーンを揃える／正解を意図的に長くしない／正解の位置を問間で分散させる／「上記すべて」「いずれでもない」を作らない）を置く。設計は geoffreylitt/explain-diff のクイズ設計指針を出典とする。
  • 理由を添えさせるのは、選択が偶然当たった場合と根拠を持って選んだ場合を記録上区別するためである。 選択が正解でも理由が差分と矛盾する場合はその問を誤答として扱う。自由記述4問より負担は軽く、判定の再現性は4択で担保される。
  • 回答があった実行で、正誤にかかわらず全問を解説する。解説には正解とその根拠（file:line）、および学習者が選んだ誤答が反映している誤解を含める。正答した問の解説も省かない。解説は <details> で折り畳む。出題の実行では正解を一切出さない（<details> に隠して置くことも行わない）。
  • 誤答した論点を別の問題に差し替えて再検証することは行わない。全問を解説する以上、解説を読んだ後の再回答は検証にならず、差し替えを繰り返す設計は終了条件を持たないため、観点3 が恒久的に未完了になりうる。ラウンド2で学習ループを閉じる。
  • 観点3 は OK・NG・判定不能 の3値を使わず、実行をまたいで持ち越す状態（未出題・出題済み・確定）を持つ。状態はマーカー行に 状態: 出題済み / 状態: 確定 として記載し、次回の実行はそこから復元する。散文からの推測に頼らない。動作は状態遷移の表で決め、ラウンド番号には依存させない。
  • 総合判定の条件から観点3の正誤を外す。完了 = 観点1 OK ∧ 観点2 OK ∧ CI green OK ∧ 観点3が確定 とし、誤答の有無は問わない。サマリには判定値ではなく状態（未回答 / 全問正解 / 誤答N問・解説済み）を書き、誤答をそのまま記録に残す。
  • 確定した観点3は覆さない。差分が変わっても再判定・再出題しない。確定後にコミットが追加されている場合は、サマリの観点3の行にその事実を添えて結果が変更前のコードに対するものであることを示す。学習者が改めて受け直したい場合は、観点3のコメントを削除して再実行すれば未出題として扱われる。
  • 確定後は観点3のコメントを投稿せず3件とする。再判定しないため、投稿しても解説を含む同じ長文が複製されるだけになる。確定済みの結果はサマリの判定表に再掲する。

Consequences​

  • 誤答しても完了に到達できるため、観点3 がタスクを恒久的にブロックすることがなくなる。ADR-023 のセルフ完結運用（マージは学習者自身が行う）と整合する。
  • 一方で、差分を読まずに4択を適当に選んでも完了に到達できる。これは受け入れる。観点3 の役割は合否を出すことではなく「自分のコードを読んだか」を記録に残すことであり、適当に答えた事実は 誤答N問 としてPRコメントに永久に残る。理由の記述を求めるのは、この記録の精度を上げるためである。メンターはラウンド2の結果を見れば、誰が自分のコードを読まずにコミットしたかを判断できる。
  • 全問解説によりコメントが長くなる。<details> での折り畳みと、確定後にコメントを投稿しない扱いで抑える。
  • 観点3 だけが状態を持つため、観点1・観点2（毎回ステートレスに再判定）と非対称になる。この非対称は意図したもので、観点1・観点2 は「PR の品質」を評価し修正すれば OK になるが、観点3 は「学習者の理解」を一度記録する性質だからである。
  • 4択化により、自由記述で得られていた理解の深さの情報は減る。理由の一文で部分的に補うが、記録の粒度は下がる。回答率の向上（PR #52 はラウンド1で10日近く停止した）との引き換えとして受け入れる。
  • ADR-025 の「理解度チェックは2ラウンド方式」「3観点すべてがOKで完了」の記述は本 ADR で置き換わる。ADR-025 側に追補のリンクを張る。
