User Stories — カレンダービュー（Issue #27）¶

分割アプローチ：Feature-Based。受け入れ基準の形式：Given-When-Then（ユーザー確認済み、2026-08-14T09:20:00Z）。各ストーリーは requirements.md のFunctional Requirements（RSV-01〜07）に対応する。

STORY-01: カレンダー形式の空き状況表示¶

As a リソース利用者 I want to リソース詳細画面を開いたときにカレンダー形式で空き状況を確認したい So that テキストリストよりも直感的に、その週の混雑感を把握できる

対応要件: RSV-01, RSV-05, RSV-06

受け入れ基準¶

  1. Given リソース利用者がリソース詳細画面（/resources/{id}）を開く When 画面が表示される Then 当週（月曜始まり）のカレンダーが週表示モードで表示される

  2. Given カレンダーが表示されている When 利用者がカレンダーの表示範囲を確認する Then 0時から24時までの時間帯が表示される

  3. Given カレンダーが表示されている When 利用者が画面を下にスクロールする Then 既存のテキスト形式の空き状況リスト（当日〜7日後）がカレンダーの下に引き続き表示されている

INVEST チェック: Independent（他ストーリーの完了を前提としない、初期表示のみ）／Negotiable（表示範囲のデフォルト値は調整可能）／Valuable（本機能の主目的そのもの）／Estimable／Small（初期表示ロジックのみ）／Testable（週開始曜日・時間帯範囲・既存リストの共存を検証可能）

STORY-02: 週表示・月表示の切り替え¶

As a リソース利用者 I want to カレンダーの表示モードを週表示と月表示で切り替えたい So that 直近の詳細な空き状況と、月単位の大まかな傾向の両方を必要に応じて見られる

対応要件: RSV-02

受け入れ基準¶

  1. Given カレンダーが週表示モードで表示されている When 利用者が「月表示」に切り替える Then 当月のカレンダーが月表示モードで表示され、その月の範囲で空き状況が再取得される

  2. Given カレンダーが月表示モードで表示されている When 利用者が「週表示」に切り替える Then 直前に表示していた期間を含む週のカレンダーが週表示モードで表示される

INVEST チェック: Independent（STORY-01の初期表示に依存するがロジックは独立）／Negotiable／Valuable／Estimable／Small（切り替えUIと再取得トリガーのみ）／Testable（切替後の表示モード・再取得呼び出しを検証可能）

STORY-03: 表示期間の前後移動¶

As a リソース利用者 I want to カレンダーの表示期間を前後に移動したい So that 来週・来月や先週・先月の空き状況も確認できる

対応要件: RSV-04

受け入れ基準¶

  1. Given カレンダーが週表示モードで当週を表示している When 利用者が「次週」を押す Then 表示が1週間後に進み、その期間の空き状況が再取得されてカレンダーが更新される

  2. Given カレンダーが週表示モードで当週を表示している When 利用者が「前週」を押す Then 表示が1週間前に戻り、その期間の空き状況が再取得されてカレンダーが更新される

  3. Given カレンダーが月表示モードで当月を表示している When 利用者が「次月」または「前月」を押す Then 表示がそれぞれ1か月後・1か月前に移動し、その月の空き状況が再取得されてカレンダーが更新される

INVEST チェック: Independent（STORY-02の表示モードに依存するが移動ロジック自体は独立）／Negotiable／Valuable／Estimable／Small（期間移動と再取得トリガーのみ）／Testable（移動後の期間・再取得呼び出しを検証可能）

STORY-04: 空き枠クリックによる予約導線¶

As a リソース利用者 I want to カレンダー上の空いている枠をクリックするだけで予約申請フォームに進みたい So that 空き状況の確認から予約申請までの操作を短縮できる

対応要件: RSV-03, RSV-07

受け入れ基準¶

  1. Given カレンダー上に予約済みでない1時間枠（例：8月20日14時〜15時）が表示されている When 利用者がその枠をクリックする Then /reservations/new?resourceId={id}&startAt=2026-08-20T14:00:00 に遷移し、予約申請フォームに開始日時が引き渡される

  2. Given カレンダー上に予約済みの枠が表示されている When 利用者がその枠を確認する Then 枠はグレーアウトされ、色だけでなくテキストまたはパターンでも予約済みであることが判別できる

  3. Given カレンダー上に予約済みの枠が表示されている When 利用者がその枠をクリックする Then 画面遷移は発生しない（クリックが無効化されている）

  4. Given 既存の OccupiedSlot の予約時間帯が1時間の枠境界と一致しない（例：14時30分〜15時30分） When カレンダーが該当時間帯の枠を描画する Then その予約と重複する枠（14時〜15時、15時〜16時）はいずれも予約済み扱いとして表示される（半開区間 [start, end) による重複判定、ResourceService.overlaps と同じ定義）

INVEST チェック: Independent（表示モード・期間移動の状態を受け取るのみで、それ自体を変更しない）／Negotiable／Valuable（受入条件で明示された中核導線）／Estimable／Small（クリックハンドラと重複判定ロジックのみ）／Testable（遷移先URL・グレーアウト表示・境界不一致時の判定を検証可能）
