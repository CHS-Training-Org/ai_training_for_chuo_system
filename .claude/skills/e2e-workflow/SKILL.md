# 結合テストのワークフローの案内

## このスキルの位置づけ

結合テストは、4つの段階を順に進める。各段階で AI が成果物を出力し、学習者が関門でレビューして「確定」か「差し戻し」を選ぶ。流れの全体は `docs-next/docs/develop/integration-test/workflow.md`（結合テストのワークフロー）にある。

このスキルがやるのは次の3つだけである。

- 状態ファイルを読み、今の段階と次にやることを示す
- 試験観点の段階で、AI の作業（`generate-test-perspectives` の呼び出しと、差し戻されたときの修正）を行う。差し戻しには、学習者がダッシュボードで選んだ仕様の食い違いへの回答が含まれることがある
- ダッシュボードを開く方法を案内する

このスキルは Opus で動く（frontmatter の `model: opus`）。モデルの指定が効くのは、利用者が `/e2e-workflow` とスラッシュコマンドで呼んだときだけで、そのターンの終わりまで続く。そのため、このスキルの中から呼び出す `generate-test-perspectives` も Opus で動く。スラッシュを付けずに頼まれて起動した場合は、セッションのモデル（Sonnet など）のまま動くので、最後の返答で `/e2e-workflow` と打ち直すよう伝える。

関門の「確定」と「差し戻し」、仕様の食い違いへの回答は、学習者がダッシュボードの画面で行う。AI の出力は実行のたびに変わり、判断を誤ることもあるため、AI が自分の出力を確定させることはしない。

## 守ること

- 状態ファイル（`state.json`）は、必ず `node scripts/e2e-workflow/state.mjs` を通して扱う。直接編集しない。
- `state.mjs` で使ってよいのは `init`、`show`、`last-return`、`validate` と、差し戻しを反映したあとの `ai-output` だけである（最初の出力のあとの `ai-output` は `generate-test-perspectives` が使う）。確定と差し戻しのコマンドは用意されておらず、作らない。
- 学習者が「確定して」と頼んできても、状態ファイルを書き換えず、ダッシュボードで確定するよう案内する。確定は学習者自身の判断として記録に残すためである。

## 手順

### Step 1: 対象画面とスラッグを決める

プロンプトから画面のパスを読み取り、`docs-next/docs/spec/screen-spec.md` の「画面一覧」と照合する。決まらなければ `AskUserQuestion` で確認する。すでに状態ファイルがある画面は `node scripts/e2e-workflow/state.mjs` の対象ディレクトリ（`Docs/test/`）の下にあるので、候補に含めてよい。

スラッグの決め方は、`.claude/skills/generate-test-perspectives/SKILL.md` の「出力」の節に従う（例：`/reservations/new` は `reservations-new`）。

### Step 2: 状態を読む

```bash
node scripts/e2e-workflow/state.mjs show <スラッグ>
```

状態ファイルがなければ作る。

```bash
node scripts/e2e-workflow/state.mjs init <スラッグ> <画面パス>
```

表示された「今の段階」と「次にやること」に従って、Step 3 に進む。

### Step 3: 今の段階に応じて動く

| 今の段階と状態 | このスキルがやること |
|---|---|
| 1 試験観点、未着手 | `generate-test-perspectives` スキルを呼び出して観点一覧（`Docs/test/<スラッグ>/perspectives.md`）を出力させる。状態を「レビュー待ち」にする更新は `generate-test-perspectives` が行うので、このスキルでは行わない。終わったら `show` で状態を確かめる |
| 1 試験観点、レビュー待ち | AI の作業はない。学習者に、`docs-next/docs/develop/integration-test/viewpoints.md` の手順3と手順4でレビューし、ダッシュボードで仕様の食い違いに回答して、確定か差し戻しを選ぶよう案内する |
| 1 試験観点、差し戻し | 下の「差し戻しを反映する」の手順で観点一覧を直し、状態を「レビュー待ち」に戻す |
| 2〜4 の段階 | このスキルはまだ AI の作業を実行しない。状態ファイルが示す手順ページ（`cases.md`、`code-generation.md`、`execution.md`）を案内するだけにする |
| すべて確定 | 完了した旨を伝える |

観点一覧のファイルがすでにあるのに、試験観点の段階が「未着手」の場合は、上書きしない。`generate-test-perspectives` も既存のファイルがあれば止まる。学習者に、既存のファイルを使うかどうかを確認する。

### 差し戻しを反映する（試験観点の段階）

学習者が差し戻した観点一覧を、指摘と仕様の食い違いへの回答に沿って直す。`generate-test-perspectives` は呼ばない。既存のファイルがあると止まるうえ、一から作り直すと出力が実行のたびに変わるため、学習者がレビューした一覧とは別物になり、指摘で参照していた ID も変わってしまうためである。

1. 差し戻しの理由と、仕様の食い違いへの回答を読む。

   ```bash
   node scripts/e2e-workflow/state.mjs last-return <スラッグ> perspectives
   node scripts/e2e-workflow/state.mjs show <スラッグ>
   ```

   差し戻しの理由には、学習者の指摘と、そのとき選んだ回答（「仕様の食い違いへの回答：…」の行）が入っている。`show` は、これまでに保存された回答をすべて表示する。

2. 観点一覧（`Docs/test/<スラッグ>/perspectives.md`）を読む。
3. 仕様の食い違いへの回答を反映する。回答があった 4.1 の行ごとに、次のようにする。
   - 「影響する観点」に回答ごとの観点案があれば、選ばれた案を2章の該当する分類へ観点として入れる。仕様根拠には、食い違う両側の記載元と、どちらに合わせたかを書く。
   - 「影響する観点」が既存の観点 ID なら、その観点を回答に合わせて直す。
   - 4.1 の「回答」列に、選ばれた選択肢の記号と案を書く（例：「A. 含めない」）。回答が選び直された場合は書き換える。ダッシュボードは、この列の先頭の記号が保存された回答と一致することで反映済みと判断する。
4. 指摘に沿って、1章から5章を直す。観点の書き方と根拠の規則は `generate-test-perspectives` の SKILL.md と出力様式に従う。次の点を守る。
   - 既存の ID は振り直さない。指摘や記録から ID で参照されているため。観点を足すときは、同じ種類の ID の最大値の続きを使う。
   - 観点を外すときは消さずに3章「確認しない観点」へ移し、理由を書く。
   - 4.1 の項目が食い違いではないと指摘されたら、両側の記載元を読み直す。一方が詳細を省いているだけなら、その行を 4.1 から外し（Q の ID は欠番のままにする）、1章の該当する行を「確定」に直し、詳しく書いている側に合わせた観点を2章に入れる。読み直しても食い違いに見える場合は 4.1 に残し、その理由を最後の返答で伝える。
   - 4.2「仕様に書かれていない点」の項目を観点にするよう指摘されたら、学習者が期待結果を書いている場合に限り、観点として足して 4.2 から外す。仕様根拠には「仕様に記載なし。学習者の判断（差し戻しの理由）」と書く。期待結果が書かれていなければ推測で補わず、最後の返答で学習者に期待結果を尋ねる。
   - 5章の集計を、直したあとの行数に合わせる。
5. 直したら、何を直したかを1〜2文にまとめて状態を「レビュー待ち」に戻す。

   ```bash
   node scripts/e2e-workflow/state.mjs ai-output <スラッグ> perspectives "差し戻しを反映：<直したことの要約>"
   ```

6. 学習者に、直した点を伝え、もう一度レビューしてダッシュボードで確定か差し戻しを選ぶよう案内する。

### Step 4: ダッシュボードを案内する

ダッシュボードが動いているかを確かめる。

```bash
curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:3130/
```

`200` 以外なら、バックグラウンドで起動する。

```bash
node scripts/e2e-workflow/server.mjs
```

学習者には、VS Code の「ポート」タブで `3130` を転送し、手元のブラウザで `http://localhost:3130` を開くよう伝える。

## 最後の返答

チャットには次だけを返す。

- 対象画面と、今の段階
- 次にやること（誰が、何を）
- ダッシュボードの URL（`http://localhost:3130/screen/<スラッグ>`）
- スラッシュを付けずに頼まれて起動した場合は、次からは `/e2e-workflow` と打つと Opus で動くこと
