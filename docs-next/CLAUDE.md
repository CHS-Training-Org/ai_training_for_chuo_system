# CLAUDE.md — docs-next 文章規範

`docs-next/` 配下の Markdown（ガイド・仕様・ADR 等）を書く・推敲するときに従う規範。`Docs/` 配下の文章規範（[`Docs/CLAUDE.md`](../Docs/CLAUDE.md)）と共通する内容が多いが、`docs-next` は Docusaurus ビルドであり、Zensical（`Docs/`）とは記法・リンク解決が異なる部分があるため、このファイルに個別にまとめる。

対象は文章そのもの（段落構成・語り口・リンクの書き方）であり、frontmatter 等の構造規約は対象外。

---

## リンクテキスト

- **ファイル名をリンクテキストにベタ書きしない**。`[coding-conventions.md §作業ブランチの作成](...)` のように書かない。リンクテキストは対象セクションの内容を表す言葉にする（`[作業ブランチの作成](...)`）。ファイル名は、それ自体が操作対象になる場面（「このファイルを Claude Code に読み込ませる」等）でのみ書いてよい。
- 同様に `ファイル名.md §セクション名` という形の表記（`curriculum.md §STEP-03` 等）も避け、セクション名だけにする（`[STEP-03](...)`）。

## 改行

- 段落内で文章が長くなる、または意味のまとまりが区切れる箇所では、行末に半角スペース 2 つを置いて改行する（Markdown のハードブレイク）。スペースなしの裸の改行はレンダリング結果に反映されないため、見た目を整えたいなら必ずスペース 2 つを付ける。
- 目安は [`Docs/CLAUDE.md` §整形](../Docs/CLAUDE.md) と同様（1 行あたり全角 70 文字程度、または話題の転換点）。
- 箇条書き・番号付きリストの項目内、表のセル内には適用しない（Markdown の構文上、意図しない挙動を招くため）。

## 主体を正確に書く

- AI-DLC ワークフロー内の記述では、実際にコードを生成・実装する主体は `/aidlc`（AI エージェント）であり、学習者ではない。「実装中の規約は〜に従ってください」のように学習者を主語にした指示文で書かず、「実装は〜の規約に沿って `/aidlc` が行います」のように主体を明示する。学習者が行うのは計画の確認・承認・セルフレビューである。

## 見出しの明示 ID

- 他ページからリンクされる見出しには、明示 ID を `## 見出し {#anchor-id}` の形で付ける。エスケープ（`\{#...}`）はしない。`.md` は `markdown.format: 'detect'` により CommonMark として解釈されるため、そのまま書ける。
- 日本語の見出しは自動生成 ID が URL エンコードされて読めなくなるため、リンク先になる見出しでは明示 ID を省略しない。
- リンクを追加・変更したら `npm run build` で確認する。`onBrokenLinks` / `onBrokenAnchors` が `'throw'` なので、存在しないページ・アンカーを指すとビルドが失敗する。

## ファイルの置き場所

`docs/` 直下にファイルを置かない。読者と目的で 5 つに分ける。

| ディレクトリ | 置くもの | 読者 |
|---|---|---|
| `learn/` | カリキュラム・環境構築・AI ツールの使い方・用語集 | 学習者（最初に読む） |
| `develop/` | 開発フロー・規約・レビュー基準・トラブルシューティング・選択課題カタログ | 学習者（実装中に引く） |
| `spec/` | 要件・画面・API・ER・エンハンス要件（真実の源） | 学習者・運営者 |
| `reference/` | アーキテクチャ・デザインシステム・ADR・Claude Code 設定・AI-DLC 台帳 | 全員（辞書的に引く） |
| `operations/` | 運用ガイド・Issue 起票手順・学習効果測定 | 運営者 |

サイドバーはこのディレクトリ構造から自動生成される（`sidebars.ts`）。ファイルを追加すれば自動で載るので、サイドバーへの手動登録は不要。並び順は frontmatter の `sidebar_position`、カテゴリのラベルは各ディレクトリの `_category_.json` で決める。

## 用語

- 見出し・本文でエンジン内部のステージ名（`Application Design`、`Functional Design` 等）をそのまま出さない。読者が初見で意味を取れないため、`develop/aidlc-guide.md` へのリンクに委ねるか、日本語の一般的な言い方（「設計ステージ」等）に言い換える。
- ファイルパスだけでなく、そのファイルが何かを一言添える（`er-diagram.md`（ER 図）等）。特に、初めてそのファイルに言及する段落では省略しない。
