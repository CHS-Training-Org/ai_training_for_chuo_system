## §共通レイアウト・ナビゲーション

### 共通レイアウト構造

全認証済み画面（`/auth/signin` を除く）は以下のレイアウトを共有する。

```
┌─────────────────────────────────────────┐
│  ヘッダー（BookFlow ロゴ ／ ユーザー名・ロールバッジ ／ サインアウトボタン）  │
├──────────┬──────────────────────────────┤
│          │                              │
│ サイド   │  メインコンテンツエリア       │
│ ナビ     │                              │
│          │                              │
└──────────┴──────────────────────────────┘
```

### ヘッダー

| 要素 | 内容 |
|------|------|
| ロゴ | 「BookFlow」テキスト or ロゴマーク。クリックで `/` へ遷移 |
| ユーザー情報 | サインイン中のユーザー名・ロールバッジ（`MEMBER` / `APPROVER` / `ADMIN`） |
| サインアウトボタン | クリックで `POST /api/auth/signout` を実行後 `/auth/signin` へリダイレクト |

## §認証

### `/auth/signin`（サインイン）

> **実装注記（ADR-008 適用）**：ADR-008（Status: Accepted）により Cognito OAuth2 ソーシャルログインを採用。以下の「メールアドレス/パスワードフォーム」記述は廃止済み。Better Auth の `signIn.social({ provider: 'cognito' })` を使用した単一ボタン方式を実装済み。

#### 画面概要

未認証ユーザー専用のサインイン画面。Better Auth + cognito-local（本番は Amazon Cognito）を経由した OAuth2 フローでサインインする。

#### UI 要素

| 要素 | 説明 |
|------|------|
| サインインボタン | クリックで Cognito OAuth2 フローを開始（`authClient.signIn.social({ provider: 'cognito' })`） |
| 開発用ロール別ログインボタン | **開発環境限定**（`NODE_ENV !== 'production'` でのみ表示）。MEMBER / APPROVER / ADMIN の各シードユーザーで cognito-local に直接ログインする（`devLoginAction` → `InitiateAuth` → IdToken を httpOnly Cookie `dev-id-token` に保存）。本番ビルドには含まれない |

#### バリデーション

Cognito 側で認証を処理するため、フォームバリデーションは不要。認証失敗時は Cognito のエラーが返る。

#### 画面フロー

1. サインインボタンクリック → Better Auth 経由で Cognito OAuth2 認可エンドポイントへリダイレクト
2. Cognito 認証完了 → コールバック URL（`/`）へリダイレクト
3. 認証失敗 → Cognito エラーページまたは `/auth/signin` に戻る

## §リソース

### `/resources`（リソース一覧、空き確認）

#### UI 要素

| 要素 | 説明 |
|------|------|
| カテゴリフィルター | 「すべて」／「会議室」／「備品」／「社用車」のタブまたはセレクト |
| キーワード検索欄 | リソース名・説明文の部分一致検索（大文字小文字を区別しない）。入力欄を空または空白のみにして絞り込むとキーワード条件は解除される。カテゴリ・空き確認期間と AND 条件で組み合わされる（`GET /api/resources` の `keyword` フィルタ仕様に準拠） |
| 並び順セレクト | 「登録日時順（デフォルト）」「名称順（昇順/降順）」「定員順（昇順/降順）」から選択。カテゴリ・空き確認期間・キーワードによる絞り込み結果に対して適用される（`GET /api/resources` の `sort` フィルタ仕様に準拠）。並び順を変更すると 1 ページ目から表示し直す |
| リソースカード一覧 | 名称・カテゴリ・場所・定員・承認フロー要否を表示。`is_active = false` のリソースは MEMBER / APPROVER には非表示（ADMIN はグレーアウトして表示） |
| 空き確認フォーム | 開始日時・終了日時の入力欄。入力後にリソース一覧を再取得し、当該時間帯に空きのあるリソースのみを表示する（占有予約のあるリソースは一覧から除外。`GET /api/resources` の `from`/`to` フィルタ仕様に準拠）。絞り込み中は対象期間と件数のメッセージを表示 |
| 「詳細を見る」リンク | リソース詳細（`/resources/{id}`）へ遷移 |
| ページネーション | page/size 方式（デフォルト 20 件/ページ） |

> **絞り込み結果 0 件時のメッセージ**：キーワードを指定して絞り込んだ結果が 0 件の場合は「絞り込み条件に一致するリソースがありません。」を表示する（空き確認期間のみ指定時は従来通り「指定した時間帯に空きのあるリソースがありません。」、いずれも未指定時は「リソースがありません。」）。

### `/resources/{id}`（リソース詳細）

#### UI 要素

| 要素 | 説明 |
|------|------|
| リソース情報 | 名称・カテゴリ・場所・定員・説明・承認フロー要否・設備一覧・利用上の注意（`equipment`・`notes` は未登録時は非表示） |
| 空き状況カレンダー | 週表示（月曜始まり、8:00〜20:00 の1時間単位グリッド）・月表示を切り替えられるカレンダー。表示期間中の占有時間帯（`status IN ('PENDING', 'APPROVED')` の予約。`GET /api/resources/{id}/availability` で取得）をグレーアウトで表示する |
| 「このリソースを予約する」ボタン | 予約申請フォーム（`/reservations/new?resourceId={id}`）へ遷移。`is_active = false` のリソースでは非表示 |

> **カレンダーの操作**
> - 「前週」「次週」（週表示）・「前月」「次月」（月表示）で表示期間を移動すると、その期間の空き情報を再取得して表示を更新する
> - 週表示では時間帯マス目、月表示では日セルをクリックすると、予約申請フォーム（`/reservations/new?resourceId={id}&startAt={開始日時}`）へ遷移する。週表示はクリックした時刻、月表示はクリックした日の既定時刻（9:00）を開始日時として引き渡す
> - 月表示の日セルは、営業時間（8:00〜20:00）が占有時間帯で完全に埋まっている場合のみグレーアウトしクリック不可にする。一部でも空きがあればクリック可能とし、実際の空き時間の確認は予約申請フォーム側に委ねる
> - `is_active = false` のリソースでは、カレンダーは表示するが空き枠のクリックは無効（「このリソースを予約する」ボタンと同様に新規予約の導線を作らない）

## §予約

### `/reservations/new`（予約申請フォーム）

#### UI 要素

| 要素 | 説明 |
|------|------|
| リソース選択 | セレクトボックス（`GET /api/resources` から取得した有効リソース一覧） |
| 開始日時 | 日付時刻入力欄（必須） |
| 終了日時 | 日付時刻入力欄（必須） |
| 繰り返し | セレクトボックス（「繰り返さない」「毎週」「毎月」。初期値は「繰り返さない」）。詳細は [繰り返し予約の入力](#reservation-recurrence-form) |
| 繰り返し終了日 | 日付入力欄。「毎週」または「毎月」を選んだときだけ表示し、必須とする |
| 利用目的 | テキスト入力欄（必須） |
| 参加人数 | 数値入力欄（任意） |
| 「申請する」ボタン | フォーム送信（`draft: false`） |
| 「下書き保存」ボタン | フォーム送信（`draft: true`）。必須項目のバリデーションは「申請する」と同じ。繰り返しの選択とも併用できる（全件が `DRAFT` で作られる） |

> `/resources/{id}` からの遷移時は `resourceId` をクエリパラメータ（`?resourceId={id}`）で受け取り、リソース選択欄に初期値として設定する。空き状況カレンダーの空き枠クリック経由の場合は、あわせて `startAt` をクエリパラメータ（`YYYY-MM-DDTHH:mm` 形式）で受け取り、開始日時入力欄に初期値として設定する。

#### バリデーション

| ルール | 条件 |
|--------|------|
| リソース必須 | リソース未選択は申請不可 |
| 開始・終了日時必須 | 両方の入力が必要 |
| 終了 > 開始 | 終了日時は開始日時より後であること |
| 繰り返し終了日の必須 | 繰り返しが「毎週」または「毎月」で、終了日が未入力の場合は送信できない（「繰り返し終了日は必須です」） |
| 繰り返し終了日の範囲 | 終了日が開始日時の日付より前の場合は送信できない（「繰り返し終了日は開始日以降にしてください」）。開始日と同じ日は有効（1 件だけ登録される） |
| 重複予約 | 申請後に 409 Conflict が返された場合、「指定した時間帯は既に予約が入っています」を表示（繰り返しの場合は、1 件でも重複があると全件が登録されない）。入力内容は保持する |

#### 繰り返し予約の入力 {#reservation-recurrence-form}

- 「繰り返し」を「毎週」または「毎月」にすると、繰り返し終了日の入力欄が現れる。「繰り返さない」に戻すと欄は非表示になり、終了日は API に送られない
- 「毎週」は開始日時と同じ曜日、同じ時刻、「毎月」は開始日時と同じ日、同じ時刻で、終了日までの予約を一括で登録する。その月に存在しない日（31 日の 2 月など）の月はスキップする。終了日当日の回を含む（[繰り返しの生成規則](./api-spec.md#post-api-reservations)）
- 登録した予約は、それぞれ独立した予約として一覧に並ぶ

#### 申請後フロー

- 「下書き保存」→ ステータスは `DRAFT`。マイ予約一覧（`/reservations`）の「下書き」タブへリダイレクト（承認フローには流れない）
- 「申請する」→ マイ予約一覧（`/reservations`）へリダイレクト
  - `requires_approval = false` のリソース → ステータスは `APPROVED`（即時確定）
  - `requires_approval = true` のリソース → ステータスは `PENDING`（承認待ち）。繰り返しの場合は件数分の承認待ちができ、承認者は 1 件ずつ承認、却下する
- 登録に成功すると、リダイレクトの前に「N 件の予約を登録しました」とトースト表示する（N は登録した件数。繰り返さない場合は「1 件の予約を登録しました」。下書き保存でも同じ）

### `/reservations`（マイ予約一覧）

#### UI 要素

| 要素 | 説明 |
|------|------|
| ステータスフィルター | 「すべて」／「承認待ち（PENDING）」／「承認済み（APPROVED）」／「却下（REJECTED）」／「キャンセル済み（CANCELLED）」／「下書き（DRAFT）」のタブ |
| リソース名検索欄 | 予約先リソース名の部分一致検索（大文字小文字を区別しない）。入力欄を空または空白のみにして絞り込むとリソース名条件は解除される。ステータスフィルター・期間フィルターと AND 条件で組み合わされる（`GET /api/reservations` の `resourceName` フィルタ仕様に準拠） |
| 期間フィルター | 開始日時・終了日時の入力欄。予約期間（開始〜終了）が指定期間と重複する予約のみを表示する（`GET /api/reservations` の `from`/`to` フィルタ仕様に準拠）。片方のみ入力して絞り込みを実行すると 400 エラーとなる（両方の指定が必須） |
| 予約一覧テーブル | リソース名・日時・目的・ステータスバッジを表示 |
| ステータスバッジ | `PENDING`=黄・`APPROVED`=緑・`REJECTED`=赤・`CANCELLED`=グレー・`DRAFT`=グレー |
| 「詳細」リンク | 予約詳細（`/reservations/{id}`）へ遷移 |
| ページネーション | page/size 方式（デフォルト 20 件/ページ） |
| 「CSV ダウンロード」ボタン | **ADMIN のみ表示**（MEMBER / APPROVER には表示しない）。ヘッダ行の「リソースを探す」の隣に置く。クリックで `GET /api/reports/reservations/csv` を呼び、現在の絞り込み（ステータス・期間 `from` / `to`）を引き継いだ CSV（`reservations_yyyyMMdd.csv`）をブラウザにダウンロードさせる。リソース名検索とページ番号は引き継がない |

> ADMIN は全ユーザーの予約一覧を閲覧できる（フィルターに申請者を絞る UI を追加してもよい）。
>
> **「すべて」タブの範囲**：「すべて」タブ（既定表示）は `DRAFT` を含まない（`PENDING`/`APPROVED`/`REJECTED`/`CANCELLED` の4ステータス）。下書きは専用の「下書き」タブでのみ表示される。
>
> **CSV ダウンロードの範囲**：ステータスを選んでいない（「すべて」タブ）場合、CSV も `DRAFT` を含まない 4 ステータスが対象になる（`GET /api/reports/reservations/csv` の `status` 未指定時の既定）。リソース名検索欄で絞り込んでいても、その条件は CSV に反映されない。

### `/reservations/{id}`（予約詳細）

#### UI 要素

| 要素 | 説明 |
|------|------|
| 予約情報 | リソース名・日時（開始〜終了）・目的・参加人数・ステータスバッジ |
| シリーズ情報 | 繰り返しで作った予約（`recurrenceType` が `NONE` 以外）だけに表示する。繰り返しの種別（毎週 / 毎月）、繰り返し終了日、シリーズ件数（「N 件」。同じ系列の全ステータスの件数）、残り回数（「N 回」。この予約より後に始まる同じ系列の予約の件数。キャンセル済み、却下済みを含み、この予約自身は含まない）。繰り返さない予約には欄を出さない。予約一覧には表示しない（`GET /api/reservations/{id}`） |
| 編集ボタン | `PENDING` または `DRAFT` の予約かつ申請者本人の場合に表示。予約編集画面（`/reservations/{id}/edit`）へ遷移 |
| キャンセルボタン | `PENDING`・`APPROVED`・`DRAFT` の予約に対して表示。クリック後に確認ダイアログを表示（`DRAFT` の場合は下書きの削除に相当する） |

#### アクセス制御

| ロール | 閲覧可能な予約 |
|--------|-------------|
| MEMBER | 自分の予約のみ |
| APPROVER | すべての予約（ただし `DRAFT` は自分が申請者の場合のみ） |
| ADMIN | すべての予約（`DRAFT` を含む） |

他人の予約に MEMBER がアクセスした場合は 403 エラーを表示する。`DRAFT` の予約に、申請者本人・ADMIN 以外（APPROVER を含む）がアクセスした場合も 403 エラーを表示する。キャンセル操作は申請者本人または ADMIN のみ可能。編集操作は申請者本人（MEMBER / APPROVER）のみ可能。

#### UI 要素

| 要素 | 説明 |
|------|------|

| 終了日時 | 日付時刻入力欄（必須・現在値を初期表示） |
| 利用目的 | テキスト入力欄（必須・現在値を初期表示） |

|------|------|

| ADMIN | 編集不可（権限マトリクス上 `PUT /api/reservations/{id}` は ADMIN 不可） |

### `/admin/reports`（利用実績、ADMIN）

**アクセス制御**：ADMIN のみアクセス可。他ロールがアクセスした場合は 403 エラー画面を表示する（集計 API も呼ばない）。

#### UI 要素

| 要素 | 説明 |
|------|------|
| 見出しと説明 | 見出しは「利用実績」。説明に、対象期間（期間未指定は「全期間」、指定時は開始日時〜終了日時）と、承認済みの予約のみを集計することを表示する |
| 期間フィルター | 開始日時・終了日時の入力欄（`datetime-local`）と「集計する」「リセット」ボタン。両方入力、または両方空のみ有効で、片方のみの入力と開始日時が終了日時以降の入力は、送信前に画面内のメッセージで止める（遷移しない）。「集計する」で URL の `from` / `to` を更新して再取得・再描画し、「リセット」で期間を外して全期間に戻す。ページを開いた直後は期間未指定（全期間） |
| エラー表示 | URL の `from` / `to` を直接指定して API が `VALIDATION_ERROR`（400）を返したときは、その文言を画面内に表示し、グラフと表は表示しない |
| 棒グラフ（予約件数） | リソースごとの承認済み予約の件数を横棒で表示する。棒の長さはこのグラフ内の最大値を 100% とした相対値。各行にリソース名と件数を併記する |
| 棒グラフ（合計利用時間） | リソースごとの合計利用時間を横棒で表示する。長さの基準と併記は上と同じ。時間は分を時間に換算し、小数第 1 位に丸めて「時間」の単位で表示する（150 分は 2.5 時間） |
| 集計表 | リソース名・予約件数・合計利用時間の 3 列。グラフと同じ値を表でも示す。並びは API の並び順（合計利用時間の降順、同値は件数の降順、さらにリソース名の昇順） |
| 空の状態 | 表示対象のリソースが 1 件もないときは、グラフと表の代わりに「表示するリソースがありません。」を表示する |

> データは `GET /api/statistics/resources` から取得する。有効なリソースは利用実績が 0 件でも件数 0・合計 0 で表示し、無効化済みのリソースは対象期間に承認済みの予約があるときだけ表示する。
>
> 画面遷移図（`screen-spec-navigation.drawio.svg`）には、この画面をまだ反映していない（図の更新は別途行う）。
