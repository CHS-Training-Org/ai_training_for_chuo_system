# 学習カリキュラム

このページは、BookFlow で学習を進める際の**学習パス**と、そこに含まれる**必須課題**を定義します。  
学習者は全員が同じ順序で課題に取り組みます。  
全体像は[学習パスマップ](#path-map)を確認してください。

---

## 学習パスマップ \{#path-map}
学習パスは 1 本です。本リポジトリ固有の環境・プロセスと AI 駆動開発の経験そのものを学習目標にしているため、全員が同じ道筋をたどります。

課題は**順序性があり**、前の課題の完了を前提に次へ進みます。STEP-03 と STEP-05 で取り組む個別の課題は、[選択課題カタログ](./develop/enhancement-catalog.md)から選びます。

| STEP    | 課題 | 内容 | 時間 | 要否 |
| ------- | ---- | ---- | ---- | ---- |
| STEP-01 | キックオフと環境構築 | オリエンテーション（集合実施もしくは録画視聴）を受けてから、DevContainer を起動し BookFlow にアクセスできる状態を作る | 4〜6 時間 | 必須 |
| STEP-02 | リポジトリ運用・開発フローの理解 | リポジトリ構成・標準開発フロー（AI-DLC）等のドキュメントを読み込む | 4 時間 | 必須 |
| STEP-03 | 初級課題1回目（AI-DLC を使わない） | 初級課題を AI-DLC を使わずに実装する | 3〜4 時間 | 必須 |
| STEP-04 | 初級課題2回目（AI-DLC を使う） | STEP-03 と同じ課題を、今度は AI-DLC を使って実装し、進め方や品質の違いを比較する | 2〜3 時間 | 必須 |
| STEP-05 | 中級課題（AI-DLC を使う） | 中級課題を AI-DLC を使って実装する | 4〜7 時間 | 必須 |
| —       | 発展課題（上級） | カタログの上級から選ぶ課題 | 課題により異なる | 任意 |

必須課題（STEP-01〜05）の合計は約 17〜24 時間です。

上記のうち STEP-03 と STEP-05 で「選択」と呼んでいるのは、どの課題をやるかを選べるという意味であり、やるかどうかは選べません。STEP-04 は新たに選ばず、STEP-03 と同じ課題を AI-DLC を使って実装し直します。難易度（初級 / 中級）は STEP ごとに決まっています。

課題に着手する際は、[コードベース理解ガイド](#codebase-understanding)を必要な範囲で参照してください。

---

## 必須ステップ課題 \{#required-steps}
学習者が最初に取り組む STEP-01〜05 の課題です。**順序性があり**、前の STEP の完了を前提に次へ進みます。

STEP-01 と STEP-02 は各 STEP の「完了条件」を自己チェックしながら進めます。  
STEP-03〜05 はいずれも選択課題（エンハンス課題）そのものであり、進め方は [標準開発フロー](./develop/dev-workflow.md#flow) を参照してください。STEP-04・STEP-05 は、PR に `@claude pr-review` とコメントして AI レビューを受け、総合判定が「完了」になることが完了条件です。STEP-03 のみ例外で、完了条件は [STEP-03 の完了条件](#step-03) を参照してください（AI レビュー・マージは行いません）。

---

## STEP-01 キックオフと環境構築
| 項目       | 内容 |
| ---------- | ---- |
| ゴール     | オリエンテーション（集合実施もしくは録画視聴）を受けてから、DevContainer を起動し、ブラウザで BookFlow のダッシュボードにアクセスできる状態を作る |
| 時間       | 4〜6 時間 |
| 参照       | 手順の詳細は [環境構築・起動手順](./getting-started.md)、トラブル時は [トラブルシューティング](./develop/troubleshooting.md) |
| AI 活用例  | 起動エラーが出たら、Claude Code にエラーメッセージを貼り付けて原因と対処法を尋ねる |
| 完了条件   | 以下の 3 点をすべて満たす<br/>- オリエンテーション（集合実施もしくは録画視聴）に参加した<br/>- `curl http://localhost:8080/actuator/health` が `{"status":"UP"}` を返す<br/>- `http://localhost:3000` でロール別ログインボタンからサインインし、ダッシュボードにサンプルデータが表示される |

:::note[録画リンクは準備中]

オリエンテーションの録画は現時点で一部しか用意できていません。視聴用リンクは準備でき次第、この節に追記します。

:::

## STEP-02 リポジトリ運用・開発フローの理解
| 項目       | 内容 |
| ---------- | ---- |
| ゴール     | このリポジトリでの開発の進め方（ブランチの切り方、学習パスの全体像、AI-DLC に基づく標準フロー）を理解し、実装を始められる状態を作る |
| 時間       | 4 時間 |
| AI 活用例  | Claude Code に [dev-workflow.md](./develop/dev-workflow.md) を読み込ませて標準フローを要約させ、自分の理解と照らし合わせて確認する |
| 完了条件   | 以下の 5 点を確認した |

実装に着手する前に、リポジトリの運用ルールを把握します。次の 5 点を確認してください。

- **学習パスの全体像**  
この[学習パスマップ](#path-map)を確認した。
- **[標準開発フロー](./develop/dev-workflow.md#flow)**  
ページ冒頭の図で、Issue 選択からマージまでの8ステップの流れと、どこを学習者が担い、どこを `/aidlc` が担うかを確認した。
- **[AI-DLC の考え方](./develop/aidlc-guide.md#plan-first)**  
plan-first（`/aidlc` を起動して AI-DLC エンジンに計画を立てさせ、提示された計画に納得してから実装する）の狙いを確認した。
- **[AI レビューの位置づけ](./develop/review-criteria.md#ai-review)**  
AI レビューの総合判定が「完了」になることがタスク完了の条件であること、観点3（理解度チェック）は4択への回答が必要で少なくとも2回のやり取りを要することを確認した。
- **[AI ツール活用ガイド](./ai-tools-guide.md)**  
Claude Code の得意な場面とセットアップ、基本的な使い方（プランモード等）を確認した。

:::tip[実際に手を動かす]

読むだけでなく、`feature/<GitHubユーザー名>/<issue番号>-<short-desc>` 形式のブランチを実際に 1 本作成してみると、以降の STEP でそのまま使えます。

:::

## STEP-03 初級課題1回目（AI-DLC を使わない） \{#step-03}
| 項目       | 内容 |
| ---------- | ---- |
| ゴール     | 本リポジトリの標準 AI ツールである Claude Code の特性を理解する。あわせて、初級の最初の選択課題を標準開発フロー（AI-DLC）を使わずに進め、後続課題で AI-DLC を使った場合との違いを体感できるようになる |
| 推定工数   | 3〜4 時間 |
| AI 活用例  | [AI-DLC を使わない開発フロー](./develop/no-aidlc-workflow.md) の手順を実際に手を動かして試す |
| 完了条件   | 初級から選んだ最初の選択課題を、[AI-DLC を使わない開発フロー](./develop/no-aidlc-workflow.md) に沿って実装する（`/aidlc` は使わず、Claude Code へ直接プロンプトする）。完了後、AI-DLC なしで進めて感じた手間を短く振り返り、その選択課題の PR に記載する（後続課題で `/aidlc` を使った場合との対比の起点にする）。この PR はマージしない（STEP-04 で同じ課題を作り直すため） |

セットアップ、使い方、効果的なプロンプトの書き方、AI 利用ポリシーは [AI ツール活用ガイド](./ai-tools-guide.md) を参照してください。

---

## STEP-04 初級課題2回目（AI-DLC を使う） \{#beginner-with-aidlc}
| 項目       | 内容 |
| ---------- | ---- |
| ゴール     | STEP-03 と同じ課題を、今度は標準開発フロー（AI-DLC）に沿って実装し直す。エンジンが計画立案・段階分割・承認ゲートで何を代行しているかを、STEP-03 との対比で説明できるようになる |
| 推定工数   | 2〜3 時間 |
| AI 活用例  | `/aidlc` を起動し、提示された Workflow Planning の内容を STEP-03 で自分が組み立てた段取りと突き合わせる |
| 完了条件   | STEP-03 で選んだ課題を、[標準開発フロー](./develop/dev-workflow.md#flow) に沿って実装する。PR に `@claude pr-review` とコメントし、AI レビューの総合判定が「完了」になったら自分のトランクブランチへマージする |

STEP-03 で書き残した「AI-DLC なしで感じた手間」と照らし合わせながら進めてください。同じ課題を 2 回繰り返すのは、AI-DLC の有無だけを変えて差を観察するためです。

## STEP-05 中級課題（AI-DLC を使う） \{#intermediate-with-aidlc}
| 項目       | 内容 |
| ---------- | ---- |
| ゴール     | フロントエンドからデータベースまでまたがる縦切り機能を、計画から実装、レビュー、マージまで自分で仕上げられるようになる |
| 推定工数   | 4〜7 時間 |
| AI 活用例  | 設計方針を検討する INCEPTION フェーズでは `/model` で Opus に切り替え、実装では Sonnet に戻す |
| 完了条件   | [中級の課題](./develop/enhancement-catalog.md#intermediate) から 1 課題を選び、[標準開発フロー](./develop/dev-workflow.md#flow) に沿って実装する。PR に `@claude pr-review` とコメントし、AI レビューの総合判定が「完了」になったら自分のトランクブランチへマージする |

複数レイヤーにまたがるため、着手前に [コードベース理解ガイド](#codebase-understanding)で対象機能の処理の流れを確認しておくと計画が立てやすくなります。

---

## コードベース理解ガイド（随時） \{#codebase-understanding}
必須課題ではありません。エンハンス課題に着手する前後で、必要な範囲だけ確認してください。

| 項目           | 内容 |
| -------------- | ---- |
| ゴール         | 着手する機能について、フロントエンド → BFF → バックエンド → DB の処理の流れと、関連する既存テストの意図を説明できる |
| 推奨タイミング | 選択課題に着手する直前、または実装中に必要になったタイミング |
| AI 活用例      | Claude Code に「〇〇機能の処理フローを説明して」「このテストが検証していない境界値は？」と尋ね、回答を手がかりに実コードを読み解く |
| 確認の目安     | 着手する選択課題の PR に、処理フローの説明やテスト意図のコメントを添える。このガイド専用の PR を別途起票する必要はない |

アーキテクチャ全体像は [アーキテクチャ](./architecture.md)、各レイヤーの責務とテスト規約は [コーディング規約](./develop/coding-conventions.md) を参照してください。[標準開発フロー](./develop/dev-workflow.md#flow) でブランチを作成したあと、実装に入る前に確認しておくと、その後の Workflow Planning での計画が立てやすくなります。
