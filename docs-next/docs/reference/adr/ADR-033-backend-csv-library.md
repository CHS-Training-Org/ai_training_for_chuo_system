# ADR-033 — バックエンド：CSV 帳票出力ライブラリ

## Status

Accepted（2026-09-11）

## Context

CSV 帳票出力機能（`GET /api/reports/reservations/csv`）の実装にあたり、CSV 本文の生成方法を選定する必要があった。候補は次の2つである。

| 候補 | 実装コスト | CSV エスケープの正しさ | 依存関係 | 数式インジェクション対策 |
|------|-----------|----------------------|---------|------------------------|
| 手書き `StringBuilder` | 低い（追加ライブラリ不要） | カンマ・改行・ダブルクォートを含む値のクォート処理を自前で正しく実装する必要があり、コーナーケースの考慮漏れのリスクがある | なし | 自前実装が必要 |
| opencsv | やや高い（ライブラリの API を学ぶ必要がある） | RFC 4180 準拠のエスケープ処理を実装に任せられる | `commons-lang3`・`commons-text`・`commons-beanutils`・`commons-collections4` を推移的に導入 | ライブラリには機能がなく、いずれにせよ自前実装が必要 |

出力データの1列（利用目的）はユーザーの自由入力であり、カンマ・ダブルクォート・改行を含みうる。手書き実装でこれを正しくエスケープするには RFC 4180 のクォート規則をすべて再現する必要があり、コーナーケースの見落としが実際の文字化け・列崩れとして表面化するリスクがある。

## Decision

**opencsv 5.12.0** を採用する。

- CSV のクォート・エスケープ処理をライブラリに任せ、自前実装によるコーナーケースの見落としを避ける
- バージョンは 2026-09-11 時点で Maven Central の `maven-metadata.xml` を確認し、5.x 系最新の安定版を採用した。Java 8 をターゲットにビルドされているため、Java 25 でも問題なく動作する
- 改行コードは opencsv の既定（`\n`）ではなく `ICSVWriter.RFC4180_LINE_END`（`\r\n`）を明示指定し、Excel との互換性を優先する

## Consequences

- **推移依存が4つ増える**：`commons-lang3`・`commons-text`・`commons-beanutils`・`commons-collections4` が compile スコープで入る。`commons-lang3` は Spring Boot の BOM が版を管理するためそちらに揃うが、残り3つは opencsv が指定するバージョンがそのまま入る。手書き実装であれば依存はゼロで済んだ
- **数式インジェクション対策は opencsv の範囲外**：opencsv にはこの対策機能がなく、`ReservationCsvWriter` 側で自前のサニタイズ（`=` `+` `-` `@` で始まる値の先頭にアポストロフィを付与）を実装する。ダブルクォートによるエスケープは対策にならない（Excel はパース時にクォートを外してから数式として評価するため）。付与したアポストロフィは Excel では表示されないが、テキストエディタや他のツールで開いた場合は見える
- **依存脆弱性スキャンは本タスクでは導入しない**：確認の結果、リポジトリに Dependabot・Renovate 等の依存脆弱性スキャンが存在しないことが判明した。これは本タスク以前からのリポジトリ全体の状態であり、単一ライブラリの追加によって悪化するものではないため、別 Issue として起票することを推奨する
- **出力件数の上限は設けない**：`StreamingResponseBody` と JPQL コンストラクタ式による DTO 射影・`@QueryHints` フェッチサイズ指定により、大量データでもメモリ消費を抑える。ただし DB コネクションを長時間占有する可能性は残る。チュートリアル規模のデータ量・ADMIN 限定という利用形態では許容範囲と判断した。将来的にデータ量が増えた場合は、期間指定の必須化・非同期ジョブ化・`spring.mvc.async.request-timeout` の設定などを検討する
