# ADR-033 — 運用：Claude Code Actions のトークン消費量を週次で収集し専用ブランチへ蓄積する

## Status

Accepted（2026-09-21）

## Context

`claude.yml`（Claude Code の GitHub Actions 統合）の利用が増え、運営側で消費量を把握する必要が生じた。把握したいのは、週単位と月単位の消費量、実行者ごとの内訳、直近 1 年の推移である。

調査の結果、消費量の取得可能性には 2 つの制約があることが分かった。

第一に、**トークン数は Actions のジョブログ本文にしか存在しない**。`anthropics/claude-code-action` は実行の最後に結果 JSON をログへ出力するが、これをアーティファクトとして保存しない。ログの保持期間は既定 90 日であり、それを過ぎた実行の消費量は取得手段が無くなる。実行の日時・実行者・回数といったメタ情報は Actions API から長期間参照できるため、「実行回数の 1 年分」と「トークン数の 1 年分」では取得可能性が異なる。

第二に、**`show_full_output` を指定しないジョブではトークン数が秘匿される**。指定なしの場合、結果 JSON に残るのはコスト（`total_cost_usd`）だけで、入出力トークン数とキャッシュトークン数は落とされる。現行バージョンでも同様の実装であることをソースで確認した。つまりトークン数の計測には、計測対象のジョブ側でこのフラグを有効にしておく必要がある。

これらを踏まえ、データの置き場所として 3 案を比較した。

| 候補 | 保持期間 | main の履歴への影響 | 参照のしやすさ |
|------|------|------|------|
| Actions アーティファクト | 既定 90 日で失効 | なし | 実行ごとに分散する |
| `main` 配下へコミット | 無期限 | 週 1 コミットが載る | リポジトリを開けば見える |
| 専用ブランチへコミット | 無期限 | なし | ブランチの切り替えが要る |

アーティファクトはログと同じ保持期間の制約を受けるため、1 年分の蓄積という目的に対して機能しない。`main` 配下は参照しやすい反面、`docs-next/` 配下に置くとドキュメントサイトのデプロイが毎週走る副作用があり、置き場所の選択が別の運用に波及する。

## Decision

**週次ワークフローでログから消費量を回収し、`metrics/claude-usage` ブランチへ蓄積する**方式を採用する。

- 収集は `claude-usage-report.yml` が担い、JST 月曜 09:00 に実行する。収集窓は 35 日とし、1 回の失敗を次回の実行で取り返せるようにする。レコードは `job_id` を一意キーとして upsert するため、窓の重複は結果に影響しない。
- 蓄積したデータ（`claude-usage.jsonl`）を唯一の長期保存先とする。集計 CSV はこの JSONL から毎回作り直す。
- トークン数を計測するため、`claude.yml` の `claude` ジョブにも `show_full_output: true` を指定する。`claude-review` ジョブでは既に有効であり、ログに展開されるのはリポジトリ閲覧権限があれば見られる内容に限られる。
- 週と月の区切りは JST で判定する。cron は UTC で動くため、集計側で明示的に変換しないと境界がずれる。
- 実行者は GitHub のログイン名で記録する。外部へ公開する段階では、蓄積したデータではなく表示側で匿名化する。

## Consequences

- **トークン数の推移は、この仕組みを動かし始めた時点から積み上がる。** 遡って取得できるのはログが残っている約 3 か月分に限られ、それ以前の実行は回数とメタ情報しか分からない。1 年分の推移が揃うのは運用開始から 1 年後である。
- `show_full_output: true` の指定により、`claude` ジョブの Actions ログの量が増える。モデルの挙動とレビュー内容には影響しない。
- 記録されるコストは list price 換算の参考値であり、実際の請求額ではない。サブスクリプション認証で実行しているため、両者は一致しない。
- ログの様式が変わるとパースが壊れる。実ログを写したフィクスチャによるテスト（`.github/scripts/lib/claude-usage.test.mjs`）を置き、様式変更を検知できるようにしている。
- データが `main` の作業ツリーに現れないため、参照するにはブランチを切り替えるか、GitHub 上でブランチを指定して開く必要がある。
