# ADR-028 — 研修リポジトリの目的と学習範囲

## Status

Accepted（2026-08-08）

## Context

BookFlow は社内エンジニアが AI 駆動開発を習得するための学習用リポジトリとして構築され、初回の学習者がすでに着手している。ところが「なぜ AI 駆動開発を習得する必要があるのか」を述べた文書は、構築から運用開始までのあいだ作られなかった。目的を記した箇所は [リポジトリ概要](../../overview.md) の一文に限られ、そこでも習得させたい内容だけが書かれている。

**目的が書かれていないと、学習者に向けた説明が一般論に留まる。** ドキュメントサイトのトップページを整える作業で、この空白が実際に問題として現れた。参照サイトが「なぜこのサイトを作ったのか」を課題の提示から書き起こしているのに対して、BookFlow 側には対応する材料がなかった。書き手が材料を持たないまま書くと、目的の記述は「実務に近い技術スタックで実践スキルを身につける」のような、どのリポジトリにも当てはまる文になる。

**業界の動向として、AI エージェントを前提とした開発フローを扱える人が求められている。** AI 活用の経験を前提とする開発体制が増えており、少人数で進める体制も広がっている。この状況では、AI エージェントを使った開発を実際に経験しているかどうかが、担当できる仕事の幅を左右する。技術スタックの選定もこの流れの上にあり、ゼロから構成を決める開発をやめて標準構成に寄せる方針は [アーキテクチャ](../../architecture.md) に記録されている。

ただし**この動向の読み取りは運営者によるものである**。上長から示されたのは学習させたい内容（Claude Code と AI 駆動開発）であり、目的や到達水準について合意を得た記録はない。以下の決定は、その依頼を運営者が解釈して具体化したものとして読む必要がある。

## Decision

**研修の学習範囲を Claude Code と AI 駆動開発に定め、学習者向けの説明は業界動向を一般化した水準で行う。**

- **学習範囲は Claude Code と AI 駆動開発とする。** 上長からの依頼をそのまま学習範囲として扱う。個別のスキル（Next.js や Spring Boot の習熟）は、AI 駆動開発を回すための土台として扱い、それ自体を到達目標には置かない。
- **手段として、既存の予約サービスを土台にしたエンハンス開発を採る。** 学習者がゼロから作るのではなく、動いているコードベースを読み解いて機能を足す形にする。AI エージェントを使う場面の多くが既存コードの理解を伴うため、その状況に近い形を選ぶ。
- **学習者向けの説明（ドキュメントサイトのトップページ）は、業界動向を一般化した水準で提示する。** AI エージェントを前提とした進め方が広がっていること、AI エージェントを使って開発できる人材が求められていることまでを書く。営業や調達の文脈に結びつく語は使わない。新人や若手が最初に読む面だからである。
- **対象は AI エージェントを使ったことがない学習者とする。** [リポジトリ概要](../../overview.md) のペルソナは中堅を「AI 駆動開発未経験」と定義しており、AI の利用経験を前提にしていない。トップページは「AI エージェント」と「AI 駆動開発」の語をその場で定義してから本題に入る。
- **検証のギャップ（モックがクエリパラメータを無視していた実例）を学習者向けの説明には使わない。** 学習者がまだコードベースを知らない時点では像が結ばず、他人の PR で起きた事象は自分の困りごとにならない。これは運営者が AI レビューを完了判定に格上げした根拠であり、記録の置き場所は [ADR-025](./ADR-025-ai-review-completion-gate.md) と本 ADR に留める。
- **トップページは Why・What・How の3セクションとし、参照サイトにある「想定する読者」に相当するセクションは置かない。** [ADR-027](./ADR-027-docusaurus-migration.md) の完了基準は「ホームページが 5gctextbook.com 風の導線を持つ」であり、参照サイトは Why・What・Who・How の4セクションを持つ。ただし参照サイトの Who は公開サイトにおける読者の自己選別（自分は対象か、時間を投資すべきか）のために機能している。BookFlow のドキュメントサイトは社内向けで、読者は指示を受けて訪れるため、この判定は到着前に終わっている。役割ごとの行き先は How の末尾に集約し、メンターとリポジトリ管理者は運用ガイドへ、Claude Code は設定台帳へ導く。セクションの欠落ではなく統合である。
- **トップページの「学習を終えたときにできること」は、現状のフローが保証する範囲ではなく、期待する到達点を書く。** [開発ワークフロー](../../develop/dev-workflow.md) の標準フローでは、計画立案から仕様更新、実装、テスト、PR 作成までを AI-DLC エンジンと各スキルが代行する。学習者に強制される行為は Issue の選択、計画への同意、理解度チェックへの回答、マージの4つに限られる。それでも到達点を書くのは、本研修の目的が上長から示された学習内容の習得であり、到達点と実態の差はカリキュラム側で埋めるべきものだからである。

## Consequences

- 目的を上長と合意していないため、[学習効果測定](../../operations/learning-effectiveness.md) が測れるのは満足度と難易度に留まる。上長が成果として読める指標（AI 駆動開発を任せられる人が増えたか）にはつながらない。合意が得られた時点で本 ADR を改訂する。
- 業界動向を一般化した水準でトップページに載せるため、学習者は「なぜこれをやるのか」をサイト上で読める。一方で、その背後にある社内の事情はリポジトリのどこにも記録していない。記録が必要になった時点で置き場所を決める。
- Context に書いた業界動向は運営者の読み取りであり、出典となる社内文書はない。後から一次資料が示された場合は、読み取りとの差分を本 ADR に追記する。
- トップページに挙げた到達点のうち、次の3つは現状のカリキュラムに支える仕掛けがない。実態との乖離をコピーの誤りとして扱うのではなく、カリキュラム側で埋める差分として扱う。
    - **AI が出したものの誤りに気づき、自分で直せる**：[ADR-026](./ADR-026-comprehension-check-quiz-format.md) は「差分を読まずに4択を適当に選んでも完了に到達できる」ことを受け入れており、検証を強制する仕組みがない。
    - **AI に任せる範囲と自分で判断する範囲を線引きできる**：STEP-03 の振り返り（AI-DLC なしで感じた手間を PR に書く）が最も近いが、線引きそのものの言語化を求める指示はない。
    - **身につけた進め方を別のコードベースで再現できる**：転用できる部分を学習者に整理させる工程がカリキュラムにない。修了時に持ち帰れるものを書かせる工程を足せば成立する。
- 学習範囲を AI 駆動開発に絞った結果、個別技術の習熟度は評価対象から外れる。学習者が Next.js や Spring Boot を理解しないまま課題を完了する余地は残る。これは受け入れる。理解度の記録は [ADR-026](./ADR-026-comprehension-check-quiz-format.md) の理解度チェックが担う。
