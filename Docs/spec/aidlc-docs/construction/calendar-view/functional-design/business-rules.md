# Business Rules — calendar-view

| # | ルール | 対応要件 / 回答 |
|---|--------|------|
| BR-01 | 週表示の30分枠は、`AvailabilitySlot[]` のいずれかの区間（`startAt`〜`endAt`）と時間的に重なる場合「予約済み」とし、グレーアウト表示してクリック不可にする | RSV-03 |
| BR-02 | 週表示の30分枠のうち BR-01 に該当しないものは「空き」とし、クリック可能にする | RSV-03 |
| BR-03 | 週表示で「空き」の枠をクリック（またはドラッグで範囲選択）すると、その選択範囲の開始日時と `resourceId` を付けて `/reservations/new` へ遷移する（予約申請フォーム側では初期値として設定されるのみで、引き続き自由入力・修正が可能。終了日時は引き継がない） | RSV-03, US-03 |
| BR-04 | 月表示の日セルは、その日に重なる `AvailabilitySlot` が1件以上あれば「予約あり」として色付けし、0件であれば「空き」として無色のまま表示する | RSV-03, 明確化質問（月表示の混雑度表現） |
| BR-05 | 月表示の日セルをクリックすると、その日を含む週の週表示に切り替える。月表示では時間枠単位のクリックによる予約フォーム遷移は行わない | RSV-06（明確化質問の回答） |
| BR-06 | 表示期間（週・月）を前後に移動すると、新しい期間に対応する `from`/`to` で空き確認 API を再取得し、カレンダー表示を更新する | RSV-04 |
| BR-07 | 週表示の時間グリッドは30分単位とする（予約申請フォームの開始・終了日時入力自体は自由入力のまま変更しない） | 明確化質問（週表示の時間グリッド） |
| BR-08 | 空き確認 API の呼び出しに失敗した場合、既存の空き確認リスト実装（`resources/[id]/page.tsx`）と同様にエラーを握りつぶし、カレンダーは「取得失敗」を示す簡潔な表示に留めて画面全体は表示を継続する | 既存実装との整合 |
| BR-09 | 既存の空き確認リスト表示は削除せず、カレンダービューと併存させる | RSV-05（Requirements Analysis での決定） |
