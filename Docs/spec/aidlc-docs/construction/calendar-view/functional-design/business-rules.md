# Business Rules — カレンダービュー（Unit: calendar-view）

| # | ルール | 出典・根拠 |
|---|--------|-----------|
| BR-01 | カレンダーの週は月曜始まりとする | RSV-06 |
| BR-02 | 週表示の時間帯は0時〜24時、1時間刻みで表示する | RSV-06 |
| BR-03 | セルの予約済み判定は半開区間`[start, end)`の重複判定（`existingStart < to && existingEnd > from`）を用い、バックエンドの`ResourceService.overlaps`と同一の定義に合わせる | RSV-07 |
| BR-04 | 1時間枠の境界と一致しない予約（例：14:30〜15:30）は、重複するすべての1時間セルを予約済み扱いにする | RSV-07、STORY-04 AC4 |
| BR-05 | 過去日時のセルも他のセルと同じ判定・クリック可否ロジックを適用し、本課題側での無効化は行わない | Functional Design時の確認事項（本書「クラリファイング質問と回答」） |
| BR-06 | 月表示は日単位の要約セルとし、1時間刻みグリッドは用いない | RSV-08 |
| BR-07 | 月表示の日セルをクリックすると、その日を含む週の週表示に切り替える（`/reservations/new`への遷移は行わない） | RSV-08 |
| BR-08 | 月表示グリッドは月曜始まりの完全な週単位で表示し、前月・翌月に属する日付を含む場合は薄いスタイルで区別する | 設計判断（一般的な月間カレンダーUIの慣行に合わせた、業務要件への影響がない表示上の判断） |
| BR-09 | 表示モードを週⇔月で切り替えてもアンカー日付は保持し、直前に見ていた期間を含む期間を表示する | STORY-02 AC2 |
| BR-10 | 表示期間を前後移動するたびに、その期間の`from`/`to`で`GET /api/resources/{id}/availability`を呼び直す。呼び出しは表示期間ナビゲーション1回につき1回とする | RSV-04、NFR（Performance） |
| BR-11 | 月表示の期間移動は、アンカー日付をその月の1日に正規化してから加減算する（日数の少ない月への遷移で月がスキップされることを防ぐ） | 設計判断（業務ロジックの正確性確保） |
| BR-12 | 予約済みセルは色に加えテキストまたはパターンでも判別できるようにする（色のみに依存しない） | 受入条件（アクセシビリティ） |
| BR-13 | 既存の空き状況テキストリスト（当日〜7日後固定）はカレンダーの表示期間と独立させ、カレンダー側のナビゲーションでは更新しない | RSV-05、Functional Design時の確認事項 |
| BR-14 | 空き枠クリック時の`startAt`は`YYYY-MM-DDTHH:mm`形式（秒なし、ローカル時刻）とし、`ReservationForm.tsx`の`<input type="datetime-local">`が扱う値の形式に合わせる | RSV-09 |
| BR-15 | `/reservations/new`は`resourceId`に加え`startAt`クエリパラメータを受け取り、フォームの開始日時欄の初期値として設定する。値が空または未指定の場合は従来どおり空欄とする | RSV-09 |
