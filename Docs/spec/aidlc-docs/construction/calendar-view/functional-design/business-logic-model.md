# Business Logic Model — calendar-view

## 概要

`/resources/{id}` のカレンダービューは、既存の空き確認 API（`GET /api/resources/{id}/availability`、フロントエンドでは `getAvailabilityAction`）が返す `AvailabilitySlot[]`（`reservationId` / `startAt` / `endAt`。課題シート上は `OccupiedSlot` と呼称）を、表示期間（週・月）に応じたカレンダーグリッドへ変換して表示する。バックエンドの変更は行わない。

## 期間（表示範囲）の算出

- **状態**：現在の表示モード（`week` | `month`）と基準日（`anchorDate`）をクライアント側で保持する
- **週表示**：`anchorDate` が属する暦週（月曜始まり）の月曜日を週の開始日とし、日曜日までの7日間を表示する。既存の空き確認リストの「当日〜7日後」という相対表示とは異なる、暦週単位の表示とする（カレンダーUIとしての週表示では暦週区切りが利用者にとって自然なため。react-big-calendar の既定ロケール設定に準拠する）
- **月表示**：`anchorDate` が属する月の1日〜末日を表示対象とする。カレンダーグリッドの体裁を保つため、月初・月末を含む週全体（前後月の日付を含む）をグリッドに表示するが、前後月の日付セルは「当月外」として視覚的に区別する
- **API 呼び出し**：表示モードに応じて算出した期間の開始日 0:00 を `from`、終了日 23:59:59 を `to` として `GET /api/resources/{id}/availability` を呼び出す（月表示でグリッドに前後月の日付を含める場合も、`from`/`to` は実際にグリッドへ表示する全期間をカバーする）
- **期間移動**：「前週・次週」操作で `anchorDate` を ±7日、「前月・次月」操作で `anchorDate` の月を ±1 して上記の算出・再取得を行う

## 空き状況データの変換

### 週表示（時間グリッド）

- 週表示は 30 分単位の時間グリッド（明確化質問の回答）でカレンダーを描画する
- 各日・各30分枠について、`AvailabilitySlot[]` のいずれかの区間（`startAt`〜`endAt`）と時間的に重なるかどうかを判定し、重なれば「予約済み」、重ならなければ「空き」とする
- 時間軸の表示範囲（0:00〜24:00 か業務時間帯に限定するか）はライブラリ（react-big-calendar）の既定の日表示範囲を採用し、特別な制限は設けない（BookFlow のリソース予約に営業時間の制約が仕様上存在しないため）

### 月表示（日セル）

- 各日セルについて、その日に重なる `AvailabilitySlot` が1件以上存在するかどうかのみを判定する（明確化質問の回答：予約有無の2値表示）
- 1件以上存在すれば「予約あり」の表示、0件であれば「空き」の表示とする。件数や時間帯の割合は表示しない

## ユーザー操作とデータフロー

1. 画面初期表示：`anchorDate = 今日`、`viewMode = week` で初期化し、該当週の `AvailabilitySlot[]` を取得してグリッドを描画する（US-01, US-02）
2. 週/月表示切り替え：`viewMode` を更新し、新しい `viewMode` に対応する期間で `AvailabilitySlot[]` を再取得する（US-02）
3. 週表示での空き枠クリック：クリックした30分枠の開始日時を `/reservations/new?resourceId={id}&startAt={ISO日時}` のクエリパラメータとして渡し遷移する（US-03）
4. 月表示での日セルクリック：`viewMode` を `week` に切り替え、`anchorDate` をクリックした日に設定する（US-04。ページ遷移は発生しない）
5. 期間移動：「前週・次週」「前月・次月」操作で `anchorDate` を更新し、新しい期間で `AvailabilitySlot[]` を再取得してグリッドを再描画する（US-05）
