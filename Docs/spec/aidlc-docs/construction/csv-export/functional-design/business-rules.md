# Business Rules: CSV 帳票出力

## BR-01: 出力範囲は常に全ユーザーの予約

ADMIN が実行する操作であるため、行レベルの所有権チェックは行わない。既存の `GET /api/reservations` が ADMIN に対して全件を返すのと同じ設計判断を踏襲する。

## BR-02: 期間フィルタは閉区間・片方のみの指定を許可

- `from` のみ指定：`from` 以降のすべて
- `to` のみ指定：`to` 以前のすべて
- 両方指定：`from` 以上 `to` 以下（両端を含む）
- 両方省略：全期間
- `from > to`：エラー（400 `VALIDATION_ERROR`）
- 判定は `reservations.start_at` のみで行う（`end_at` は判定に使わない。長時間予約が期間をまたぐ場合でも、開始日時が範囲内であれば対象に含める）

## BR-03: ステータスフィルタは省略時に全ステータス

`status` を指定しない場合、`DRAFT`・`PENDING`・`APPROVED`・`REJECTED`・`CANCELLED` のすべてを対象とする（既存の `GET /api/reservations` の `status` フィルタと同じ挙動）。

## BR-04: CSV インジェクション対策はユーザー由来の3列のみに適用する

対象列：**リソース名**・**申請者名**・**目的**。これらの先頭文字が `=` `+` `-` `@` またはタブ・復帰（CR）である場合、アポストロフィ（`'`）を先頭に付与する。

対象外：予約 ID・開始日時・終了日時・承認状態。これらは機械生成された値であり、意図しない先頭文字を持つことはないため、サニタイズを適用すると値を不必要に汚染する。

**根拠**: opencsv にはこの対策機能がなく、ダブルクォートによる CSV エスケープは Excel の数式解釈を防がない（Excel はパース時にクォートを外してから評価するため）。

## BR-05: 承認状態は日本語ラベルで出力する

| DB 値 | CSV 表示 |
|---|---|
| `DRAFT` | ドラフト |
| `PENDING` | 承認待ち |
| `APPROVED` | 承認済み |
| `REJECTED` | 却下 |
| `CANCELLED` | キャンセル済み |

フロントエンドの `RESERVATION_STATUS_LABELS`（`labels.ts`）と表記を統一する。

## BR-06: 日時は Excel が日付として認識できる形式で出力する

`yyyy/MM/dd HH:mm`（秒は含めない）。API の JSON レスポンスが使う ISO 8601 形式（`T` 区切り）のまま出力すると、Excel がテキストとして扱い日付ソート・フィルタが機能しなくなるため、帳票専用の書式に変換する。

## BR-07: 0件の場合もエラーにしない

絞り込み条件に合致する予約が1件もない場合、ヘッダ行のみの CSV を返す（200 OK）。空の結果はエラーではなく正常な業務結果として扱う。

## BR-08: ストリーミング開始後の障害は業務エラーとして扱わない

レスポンスのステータス・ヘッダが確定した後（ストリーミング開始後）に発生した障害（DB 接続断・クライアント切断等）は、JSON エラーとして返却できない。この場合クライアントは途中で切れた CSV を受け取ることになるが、これは想定内の技術的制約として `api-spec.md` に明記し、隠さない（BR-01〜07 の業務ルールはすべてストリーミング開始前に確定させることで、この制約が実際に問題になる場面を最小化している）。
