# Business Logic Model: CSV 帳票出力

## 中核の業務プロセス

1. **フィルタ条件の解決**: 管理者が入力した期間・ステータス（いずれも任意）を、データ取得可能な確定条件に変換する
2. **対象データの選定**: `reservations` テーブルから、`start_at` が指定期間内かつ `status` が指定集合に含まれる予約を、リソース名・申請者名を結合した形で取得する
3. **表示用への変換**: 取得した予約データを、Excel で正しく表示できる形式（日本語ラベル・日時書式・数式インジェクション対策済みの文字列）に変換する
4. **ファイルとしての出力**: 変換済みデータを CSV 形式でクライアントに送出する

## データ変換フロー

```
reservations (start_at, end_at, purpose, status)
  + resources.name（JOIN）
  + users.name（JOIN、申請者）
       ↓ フィルタ（期間・ステータス）
  ReservationCsvRow（id, resourceName, requesterName, startAt, endAt, purpose, status）
       ↓ 表示用変換（ReservationCsvWriter）
  CSV の1行（予約ID, リソース名, 申請者名, 開始日時, 終了日時, 目的, 承認状態）
```

## 業務プロセスの境界

- **含む**: 予約データの取得・絞り込み・CSV への変換
- **含まない**: 承認ワークフローの操作（承認・却下）、予約自体の作成・更新・キャンセル。本機能は読み取り専用の帳票であり、既存の予約ドメインの状態を一切変更しない

## 誤用シナリオ（Security Baseline SECURITY-11 に対応）

- **大量データによる長時間接続の占有**: 期間・ステータスを指定せずに全件を要求された場合、DB コネクションを長時間占有する可能性がある。対策として `Stream` + フェッチサイズ指定でメモリ消費を抑えるが、コネクション占有時間そのものは短縮しない。チュートリアル規模では許容し、ADR-033 に将来の対応案（期間の必須化等）を記録する
- **利用目的への悪意ある入力**: `purpose` は自由入力であり、CSV を Excel で開いたときに数式として実行される可能性がある（数式インジェクション）。対策は `business-rules.md` を参照
