# E2E Test Instructions（recurring-reservation）

## 判定

- **Playwright の E2E は追加も変更もしていない**：既存の `reservation-flow.spec.ts` は「繰り返さない」の申請で、ラベル（`開始日時 *` など）と遷移（`/reservations`）が変わらない。繰り返しの挙動は、単体テストと結合テストで検証している
- **ブラウザでの実機確認は未実施**：下記の手順を、PostgreSQL と cognito-local が動く開発環境で行う

## 準備

```bash
docker compose -f .devcontainer/docker-compose.yml up -d
bash scripts/provision-cognito.sh          # 初回のみ
cd backend && ./gradlew bootRun            # http://localhost:8080（Flyway が V003 を適用する）
cd frontend && pnpm dev                    # http://localhost:3000
```

ブラウザサインインはローカルで動かないため、サインイン画面の「開発専用ロール別ログインボタン」を使う。

## 手順 A: 繰り返し予約の基本（MEMBER）

1. `/reservations/new` を開く。**期待**：「繰り返し」が「繰り返さない」で、終了日の欄は出ない
2. 「毎週」を選ぶ。**期待**：「繰り返し終了日 *」の欄が現れる。終了日を空のまま「予約を申請する」を押すと、「繰り返し終了日は必須です」が出て送信されない
3. 開始日の前日を終了日にする。**期待**：「繰り返し終了日は開始日以降にしてください」
4. 承認不要のリソース、開始を来週の月曜 10:00、終了日をその 3 週間後にして申請する。**期待**：「4 件の予約を登録しました」のトーストが出て、`/reservations` に 4 件が別々に並ぶ。一覧にシリーズの表示はない
5. 2 回目の予約の詳細を開く。**期待**：繰り返しが「毎週」、終了日、シリーズ件数「4 件」、残り回数「2 回」
6. 3 回目をキャンセルし、2 回目の詳細を開き直す。**期待**：シリーズ件数は 4 件、残り回数は 2 回のまま（全ステータスを数える）
7. 「繰り返さない」で 1 件申請する。**期待**：「1 件の予約を登録しました」。その詳細にシリーズの欄は出ない
8. 「毎月」を、31 日開始で 5 か月分申請する。**期待**：31 日がない月はスキップされる

## 手順 B: 重複と下書き・承認

1. 手順 A の 4 の予約と、1 回だけ時間が重なる繰り返しを申請する。**期待**：「指定した時間帯は既に予約が入っています」が出て、入力は残り、1 件も登録されない（一覧で確認）
2. 8 日間（例：月曜 10:00 から翌週月曜 10:00）の予約を「毎週」で申請する。**期待**：同じ文言で拒否される（自己重複）
3. 「下書き保存」と「毎週」を併用する。**期待**：トーストのあと `/reservations?status=DRAFT` へ遷移し、全件が下書き
4. 承認が必要なリソースで申請する。**期待**：全件が承認待ち。APPROVER でサインインした承認待ち一覧に件数分が並び、1 件ずつ承認・却下できる

## 手順 C: ロック下の一括作成（件数上限なしの確認）

1. **所要時間**：終了日を 1 年後にした「毎週」（約 53 件）と、2 年後（約 105 件）で申請し、登録にかかる時間を測る。**期待**：数秒以内。極端に遅い場合は、上限件数の導入を検討する（`business-logic-model.md` のリスク）
2. **同時申請**：同じリソースに、同じ時間帯を含む繰り返しを、2 つのブラウザから同時に申請する。**期待**：片方だけが成功し、もう片方は 409。両方が成功しない（リソース行の悲観ロックによる直列化）
