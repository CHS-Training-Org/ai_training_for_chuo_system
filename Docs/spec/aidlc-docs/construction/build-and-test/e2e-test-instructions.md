# End-to-End Test Instructions — `resource-keyword-search`

## 現状

本リポジトリの Playwright は雛形（`frontend/tests/e2e/example.spec.ts`）のみで、実機能の E2E テストは未整備である。CI（`CI Frontend`）も `pnpm test:e2e` を実行しない。したがって**本ユニットでは自動 E2E テストを追加しない**。既存機能の E2E 整備は別のエンハンス課題（既存機能の E2E テスト追加）が担当する。

その代わり、画面操作で確認すべき項目を手動確認手順として以下に定める。

## 手動確認の準備

```bash
# ローカルサービスの起動
docker compose -f .devcontainer/docker-compose.yml up -d

# バックエンド
cd backend && ./gradlew bootRun

# フロントエンド
cd frontend && pnpm dev
```

`http://localhost:3000` を開き、サインイン画面の**開発専用ロール別ログインボタン**を使う。ブラウザからの Cognito サインインはローカルでは動作しない（cognito-local が http:// のため Better Auth の OAuth リダイレクトが失敗する）。

## 確認前の準備

`scripts/seed.sql` が投入するリソース 3 件（第1会議室・プロジェクターA・社用車A）はいずれも `is_active = TRUE` である。項目 10 と 11 のロール差を確認するには、先に ADMIN で `/admin/resources` を開き、いずれか 1 件を無効に切り替えておく。

## 「リセット」で入力欄が空にならない件

項目 6 の期待値は当初「キーワード入力欄が空になる」としていたが、実装の挙動と食い違っていたため修正した。

`handleReset` は `router.push("/resources")` で URL を変えるだけである。フィルタフォームの各入力は非制御コンポーネント（`defaultValue`）であり、`defaultValue` はマウント時にしか反映されない。App Router 内の遷移では `ResourceFilterForm` が再マウントされないため、DOM 上の入力値は維持される。

これはキーワード追加以前からの挙動であり、カテゴリと日時の各入力でも同様に起きる。本課題では既存挙動を変更しない。

## 実施結果

上記 12 項目は 2026-09-16 に学習者が手動で実施し、すべて期待どおりの結果となった（項目 6 は上記の修正後の期待値で確認）。

### エスケープ確認に用いた入力

ローカルのシードデータには `%` と `_` を含むリソースが存在しないため、エスケープが壊れていれば全件が一致し、正しければ 0 件になる。この差で判別できる。

| 入力 | 正しい結果 | 壊れているときの結果 |
|---|---|---|
| `%` | 0 件 | 3 件（全件） |
| `会議%室` | 0 件 | 1 件（第1会議室） |
| `_` | 0 件 | 3 件（全件） |
| `第_会議室` | 0 件 | 1 件（第1会議室） |

0 件を期待する確認だけでは検索そのものの故障と区別できないため、次の対照と必ず組み合わせる。

| 入力 | 期待 | 確認できること |
|---|---|---|
| `プロジェクター` | 2 件（第1会議室・プロジェクターA） | 名称と説明文の双方が検索対象（第1会議室は説明側での一致） |
| `会議` | 1 件（第1会議室） | 名称への部分一致 |
| `4k` / `4K` | いずれも 1 件（プロジェクターA） | 大文字小文字を区別しない |

### 最大長の確認

入力欄には `maxLength={100}` を付けているため、ブラウザからは 101 文字を入力できない。101 文字を貼り付けると 100 文字に切り詰められることを確認する。

`400 Bad Request` を画面から引き起こすには URL に直接 101 文字の `keyword` を与える必要があるが、本リポジトリには `error.tsx` が無いため Next.js の既定エラー画面になる。これは `from` のみを指定した場合など既存の検証エラーでも同じであり、本課題が持ち込んだ挙動ではない。400 の検証は `list_withKeywordExceeding100Chars_returns400ValidationError` が自動で行うため、画面操作では切り詰めの確認で足りる。

## 将来の E2E テスト追加への備え

キーワード入力欄には `data-testid="resource-filter-keyword-input"` を付与してある。E2E 整備の課題に着手する際は、この属性でセレクタを組み立てられる。既存の他要素には `data-testid` が無いため、その課題ではまとめて付与することになる。
