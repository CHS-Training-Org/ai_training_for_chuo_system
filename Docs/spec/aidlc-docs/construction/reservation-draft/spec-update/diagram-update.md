## 対象ファイル

`docs-next/static/diagrams/spec/` には、同じ図が2つの形式で置かれている。

| ファイル | 役割 |
|---|---|
| `*.drawio` | 図の定義（プレーンな XML） |
| `*.drawio.svg` | サイトが実際に表示する SVG。描画結果に加えて、同じ XML を圧縮して `content` 属性に埋め込んでいる |

Markdown が参照しているのは `.drawio.svg` のほうである。
`.drawio` だけを更新してもサイト上の図は変わらない。

**ファイル名は1対1で対応する。** 片方の XML をもう一方に貼り込むと図の中身が入れ替わる。

| `.drawio` | 対応する `.drawio.svg` |
|---|---|
| `requirements-reservation-status.drawio` | `requirements-reservation-status.drawio.svg` |
| `screen-spec-navigation.drawio` | `screen-spec-navigation.drawio.svg` |

## 更新の方法

この開発環境に drawio の CLI はないため、当初は VSCode の `hediet.vscode-drawio` 拡張で再出力する想定だった。
実際には次の手順で生成した。手作業は不要である。

1. `.drawio` に図形と線を追加する。
2. `.drawio.svg` の描画部分（`<g>` 要素）に、対応する図形と線を同じ座標系で追記する。
   座標系は「モデル座標から図全体の左上を原点に平行移動したもの」であり、ステータス遷移図は `(-70, -20)`、画面遷移図は `(-50, -20)` のずれを持つ。
3. `.drawio` の `<mxGraphModel>` を URL エンコード、raw deflate、Base64 の順に変換して `.drawio.svg` の `content` 属性に書き戻す。
   変換の往復が元の XML と一致することを検証したうえで実施した。
4. Playwright の Chromium で SVG を画像に描画し、目視で確認した。

生成に使ったスクリプトは作業用ディレクトリに置いた（リポジトリには含めない）。
以降この図を編集するときは、VSCode で `.drawio.svg` を直接開いて drawio のエディタで編集し保存すれば、拡張が描画部分と埋め込み XML の両方を書き出す。

### 検証で見つかった不具合

`content` 属性を正規表現 `content=".*?" ` で置換したところ、この属性が `<svg>` の最後の属性で `">` で終わるため、照合が属性の外まで伸びて `<svg>` タグを壊した。
Chromium が「Attribute style redefined」として検出したので、引用符を含まない範囲で切り出す方式に改めた。
描画して確認していなければ、壊れた SVG をそのままコミットしていた。

## 図に加えた変更

### 予約ステータス遷移図

追加したノード1件。

| ID | 内容 | 位置・大きさ（モデル座標） | 配色 |
|---|---|---|---|
| 19 | `DRAFT` | x=70, y=20, 幅170, 高さ60 | 塗り `#f8fafc` / 線 `#475569` |

追加した矢印3件。

| ID | 始点 | 終点 | ラベル |
|---|---|---|---|
| 20 | 開始（黒丸） | `DRAFT` | 下書き保存（draft=true） |
| 22 | `DRAFT` | `PENDING` | 正式申請（要承認） |
| 23 | `DRAFT` | `APPROVED` | 正式申請（承認不要） |

`DRAFT` は `PENDING` の真上、開始の黒丸の左に置いた。

当初は `DRAFT` から `DRAFT` への自己ループ（内容の編集）も入れる予定だったが、落とした。
理由は2つある。
第一に、ループを左側に回すと図の外形が左に広がり、既存の全要素の座標を平行移動し直す必要が生じる。
第二に、既存の図は `PENDING` の内容編集（`PENDING` から `PENDING`）も描いておらず、片方だけ描くと不揃いになる。
下書きを編集してもステータスが変わらないことは、[要件定義の下書き保存](../../../../../../docs-next/docs/spec/requirements.md)の遷移表に記してある。

ラベルの文言は、既存の `(requires_approval=true)` 形式ではなく「（要承認）」「（承認不要）」とした。
既存ラベルが占める帯（図の上部 y=53 から 77）を避けて配置する必要があり、長いラベルでは重なるため。
