# Story Generation Plan — recurring-reservation

## 方針

- **Breakdown Approach**: Feature-Based を基本とし、承認が必要なリソースの N 件承認（APPROVER の視点）だけは Persona-Based の要素を取り入れたハイブリッドとする
- **ペルソナ**: 2 ペルソナ（MEMBER：繰り返し予約を申請する、APPROVER：N 件の承認ステップを個別に処理する）。ADMIN も予約を作れるが、予約作成の挙動は MEMBER と同じため別のペルソナは立てない
- **粒度**: 要件（REC-01〜12）と受入条件 15 項目に対応する 8 ストーリーに分解する
- **フォーマット**: 「〜として、〜したい。それによって〜できる」形式 + Gherkin 形式の受入条件（既存ユニットの stories.md と同じ形式を踏襲）

## 実行チェックリスト

- [x] Step A: `personas.md` を生成する（MEMBER・APPROVER の 2 ペルソナ）
- [x] Step B: `stories.md` を生成する。以下の 8 ストーリー候補を INVEST 基準で検証しながら作成する
  - US-01 毎週の繰り返し登録（開始日から終了日まで同じ曜日・時刻、終了日当日の回を含む、日をまたぐ予約も同じ長さ、レスポンスは配列で `startAt` の昇順）
  - US-02 毎月の繰り返し登録（毎月同じ日、存在しない日の月はスキップ、スキップ後は基準日から数える）
  - US-03 重複時の全件失敗（既存の予約との重複、生成した予約どうしの自己重複、どちらも 409 で何も作られない。メッセージに衝突日は含めない。承認者不在の 422 でも全件ロールバック）
  - US-04 繰り返し指定の検証と従来互換（「繰り返さない」が初期値で 1 件の配列、`NONE` で終了日は 400、`WEEKLY` / `MONTHLY` で終了日未指定は 400、終了日が開始日より前は 400、終了日が開始日と同じなら 1 件）
  - US-05 下書き・承認が必要なリソースとの併用（全件 `DRAFT`、全件 `PENDING` と N 件の承認ステップ、承認者が件ごとに承認・却下する）
  - US-06 個別の予約としての管理（予約一覧に個別に表示、それぞれ詳細確認・キャンセル・編集ができ、他の回に影響しない）
  - US-07 フォームでの繰り返し入力と登録結果（Select と終了日の表示切替、登録成功のトースト、409 のエラー表示、下書き併用時の遷移）
  - US-08 詳細画面のシリーズ情報（種別・終了日・シリーズ件数・残り回数を表示、一覧には出ない、「繰り返さない」の予約には出ない）
- [x] Step C: 各ストーリーに受入条件（Gherkin 形式）を記載し、requirements.md の受入条件 15 項目をすべてカバーしていることを確認する（V003 の実行と既存データへの影響、既存テストの pass、日付生成のユニットテストは、US-01〜US-04 のテスト観点と非機能要件として対応付ける）

## 確認事項

requirements.md の決定事項（12 件）と既定の前提（7 件）により、ストーリー作成に必要な曖昧点はすべて解消済みと判断する。追加の確認質問はない。ストーリーの分け方（8 件）に違和感があれば、承認時に Request Changes で指定してほしい。
