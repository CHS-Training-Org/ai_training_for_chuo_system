# Personas

対象：リソース一覧のキーワード検索追加
ロールの定義元：`docs-next/docs/spec/requirements.md`（§ロールと権限）、`backend/src/main/java/com/example/bookflow/domain/Role.java`

BookFlow は `MEMBER` / `APPROVER` / `ADMIN` の3ロールを持つ。本課題で振る舞いに差が出るのは検索結果の母集合だけであり、その差は ADMIN と非 ADMIN の間にのみ存在する。APPROVER は承認権限を追加で持つが、リソース一覧の可視範囲は MEMBER と同一である。

---

## P-01 一般社員（`MEMBER`）

- **役割**: 会議室・備品・車両を予約して業務に使う。本課題の主要ペルソナ。
- **目的**: 目当てのリソースを素早く見つけて予約に進む。
- **利用文脈**: 打ち合わせの直前など、時間の限られた場面でリソース一覧を開く。カテゴリだけでは候補が絞りきれず、名称や説明文の記憶（「プロジェクターがある部屋」「第2会議室だったはず」）を手がかりに探す。
- **本課題での関心事**:
  - 覚えている語句で一覧を絞り込めること。
  - 入力の大文字小文字を気にせずに済むこと。
  - カテゴリ・利用したい時間帯との組み合わせで絞り込めること。
  - 絞り込みをやり直すとき、キーワードだけを外せること。
- **可視範囲**: `isActive = true` のリソースのみ。無効リソースは検索しても現れない。
- **技術的習熟度**: 一般的な業務アプリの操作に慣れている。検索構文（ワイルドカード等）の知識は前提にできない。

## P-02 承認者（`APPROVER`）

- **役割**: MEMBER の全権限に加え、担当リソースの予約を承認・却下する。
- **目的**: 自身の予約を取るときは MEMBER と同じ。承認業務の前後に対象リソースを確認することがある。
- **本課題での関心事**: P-01 と同一。
- **可視範囲**: `isActive = true` のリソースのみ（MEMBER と同一）。
- **ストーリー上の扱い**: 本課題では MEMBER と振る舞いが完全に一致するため、独立したストーリーを立てない。P-01 のストーリーがそのまま適用される。

## P-03 管理者（`ADMIN`）

- **役割**: リソースの登録・更新・有効無効の切り替え、ユーザー管理。
- **目的**: リソース台帳を維持する。無効化したリソースを含めて現況を把握する。
- **利用文脈**: リソース件数が多いため、台帳の確認や再有効化の判断のときに、無効リソースも含めた検索で対象を特定したい。
- **本課題での関心事**:
  - 無効リソースも検索対象に含まれること。
  - 検索結果の中で有効・無効が視覚的に区別できること（既存のグレーアウト表示と「無効」バッジ）。
- **可視範囲**: `isActive` の値によらず全リソース。
- **技術的習熟度**: システムの内部構造をある程度理解している。

---

## ペルソナ間の差分

| 観点 | P-01 MEMBER | P-02 APPROVER | P-03 ADMIN |
|---|---|---|---|
| 検索結果に無効リソースを含む | 含まない | 含まない | 含む |
| キーワードの照合対象 | `name` / `description` | 同左 | 同左 |
| カテゴリ・期間との併用 | 可 | 可 | 可 |
| 本課題で独立したストーリーが必要か | 必要 | 不要（P-01 と同一） | 必要（可視範囲の差） |
