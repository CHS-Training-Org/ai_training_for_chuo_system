# Personas — reservation-draft

## ペルソナ1：MEMBER（下書きの作成者）

- **役割**: 一般社員。会議室・設備の予約を申請する
- **特性**: 複雑な予約（目的・参加人数の確認が必要な場合等）を、確定前に一旦保存しておきたい
- **動機**: 入力途中の予約を失わずに保存し、後から内容を詰めて正式に申請したい。他人に下書きの内容を見られたくない

## ペルソナ2：APPROVER（承認者）

- **役割**: 要承認リソースの予約申請を承認・却下する
- **特性**: 承認一覧（`/approvals`）には正式に申請された（`PENDING`の）予約のみが表示されることを期待する
- **動機**: 他人がまだ正式申請していない下書きの段階の内容を、承認一覧や予約一覧で目にしたくない（承認対象ではないものを見せられても判断できない）

## ペルソナ3：ADMIN（管理者）

- **役割**: 全予約・全リソースを管理する
- **特性**: 運用上の必要があれば、他人の下書きも含めて全件を把握できる立場
- **動機**: トラブル対応・利用状況の把握のため、下書きを含むすべての予約データにアクセスできる必要がある
