# Personas — usage-report

## ペルソナ1：ADMIN（管理者）

- **役割**: 全予約・全リソースを管理する
- **特性**: リソースの稼働状況を見て、増設・廃止・運用の見直しを判断する。月ごとや四半期ごとなど、期間を区切って比較したい場面が多い
- **動機**: どのリソースがどれだけ使われているかを、件数と時間の両方で一目で把握したい。まったく使われていないリソースも一覧に出て、廃止の候補として見つけたい

## ペルソナ2：MEMBER（一般社員）

- **役割**: 会議室・設備の予約を申請する
- **特性**: 自分の予約だけを閲覧できる立場。全リソースの利用実績を見る権限はない
- **動機**: 利用実績の機能があっても、自分の権限で他人の利用状況が見えることはないと期待する（ナビにも出ず、API を直接呼んでも 403）

## ペルソナ3：APPROVER（承認者）

- **役割**: 要承認リソースの予約申請を承認・却下する
- **特性**: 承認業務のために予約の一部を閲覧できるが、全リソースの利用実績の集計は ADMIN の権限に限られる
- **動機**: MEMBER と同様に、承認者の権限では統計を取得できないことが、情報の取り扱いルールとして一貫していてほしい
