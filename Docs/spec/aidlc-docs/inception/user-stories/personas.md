# Personas — recurring-reservation

## ペルソナ1：MEMBER（一般社員）

- **役割**: 会議室・設備の予約を申請する。ADMIN も予約を作れるが、予約作成の挙動は MEMBER と同じため、このペルソナに含めて扱う
- **特性**: 毎週月曜の定例会議や月次の報告会など、決まった曜日・日付に同じリソースを使う場面が多い。予約申請フォームで日時とリソースを入力するが、繰り返しの回数分を毎回個別に申請するのは手間に感じている
- **動機**: 開始日と終了日を決めて 1 回で登録したい。どこかの回に既存の予約と重なるときは、中途半端に登録されず、全体がやり直せる状態でいてほしい。登録した後は、1 回ごとに独立した予約として、必要な回だけキャンセルや変更ができてほしい

## ペルソナ2：APPROVER（承認者）

- **役割**: 要承認リソースの予約申請を承認・却下する
- **特性**: 承認が必要なリソースで繰り返し予約が申請されると、承認画面に件数分の申請が個別に並ぶ。まとめて承認する手段はなく、1 件ずつ判断する
- **動機**: 繰り返しの各回を、通常の予約と同じ手順で、1 件ずつ承認・却下できてほしい。却下した回だけが却下になり、ほかの回に影響しないことを期待する
