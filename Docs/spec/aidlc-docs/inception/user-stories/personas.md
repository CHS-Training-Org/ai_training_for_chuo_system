# Personas — 予約の下書き保存（Issue #30）

新規ペルソナは追加しない。既存の3ロール（`docs-next/docs/spec/requirements.md` §認証・§予約）を、本タスクに関係する特性のみに絞って記述する。

## MEMBER（申請者本人）

- **役割**: リソースを予約する一般社員。本機能の主な利用者
- **本タスクでの動機**: 予約に必要な情報（日時・目的・参加人数）がまだ固まっていない、または申請前にもう一度内容を見直したい場合に、申請を確定させずに保存しておきたい
- **本タスクでできること**: 自分の下書きの作成・閲覧・再編集・正式申請・削除（キャンセル）
- **本タスクでできないこと**: 他人の下書きの閲覧・操作（`requirements.md` D4）

## APPROVER（承認者）

- **役割**: `requires_approval=true` のリソースの予約を承認・却下する
- **本タスクでの動機**: 通常は自分が担当する承認待ち予約のみに関心があり、他人が作成途中の下書きは承認対象でも業務上関知する対象でもない
- **本タスクでできること**: `PENDING`/`APPROVED`/`REJECTED`/`CANCELLED` の予約は既存どおり全件閲覧できる。自分自身が申請者であれば自分の `DRAFT` を通常のMEMBERと同様に操作できる
- **本タスクでできないこと**: 他人が作成した `DRAFT` の閲覧・操作（`requirements.md` D4。既存の「APPROVERは全件閲覧可」という前提から `DRAFT` に限り外れる例外ロール）

## ADMIN（管理者）

- **役割**: システム全体の管理者
- **本タスクでの動機**: 利用状況の把握・トラブル対応のため、他人の下書きも含めて全予約を閲覧できる必要がある
- **本タスクでできること**: 他人の `DRAFT` を含む全予約の閲覧（既存どおり、`DRAFT` に対しても例外なく維持される唯一のロール）。既存の `cancel()` の所有権チェック（申請者本人 or ADMIN）を `DRAFT` にもそのまま適用するため、他人の `DRAFT` のキャンセル（削除相当）もできる
- **本タスクでできないこと**: 他人の `DRAFT` の内容編集・正式申請（`PUT /api/reservations/{id}`）。既存の `update()` に ADMIN 例外はなく、`PENDING` の予約も ADMIN は編集できない（`screen-spec.md` の既存制約）のと同じ扱いを `DRAFT` にも適用する
