# Personas — 予約の下書き保存

**対象**: 予約の下書き保存（`docs-next/docs/spec/enhancements/intermediate/reservation-draft.md`）
**ロールの定義元**: `docs-next/docs/spec/requirements.md`（ロールと権限）、`backend/src/main/java/com/example/bookflow/domain/Role.java`

BookFlow は `MEMBER` / `APPROVER` / `ADMIN` の3ロールを持つ。
本課題では3ロールすべてで振る舞いに差が出る。
とくに APPROVER は、既存の権限モデルでは全予約を閲覧できるにもかかわらず、`DRAFT` だけは閲覧できなくなる。
既存の権限が狭まる唯一のロールであり、実装時に見落としやすい。

---

## P-01 一般社員（`MEMBER`）

- **役割**: 会議室・備品・車両を予約して業務に使う。本課題の主要ペルソナ。
- **目的**: 内容が固まりきらない予約を、申請せずに取り置いておく。後で落ち着いて内容を詰めてから申請する。
- **利用文脈**: 参加人数や利用目的の確認が終わっていない段階で予約フォームを開く。
  会議の候補日時だけは決まっているが、関係者への確認待ちで正式に申請できない。
  いったん保存して席を立ち、確認が取れてから戻ってくる。
- **本課題での関心事**:
  - 入力した内容を、申請せずに保存して離れられること。
  - 保存した下書きを一覧から迷わず見つけられること。
  - 戻ってきたときに内容を直せること。
  - 内容が固まったら、その場で正式申請に進めること。
  - 下書きのままでは誰にも承認依頼が飛ばないこと。
- **可視範囲**: 自分の予約のみ。下書きも自分のものだけが見える。
- **本課題で新たにできるようになること**: 予約を `DRAFT` で保存し、再編集し、正式申請する。
- **技術的習熟度**: 一般的な業務アプリの操作に慣れている。ステータスの内部名称（`DRAFT` 等）は意識しない。

## P-02 承認者（`APPROVER`）

- **役割**: MEMBER の全権限に加え、担当リソースの予約を承認・却下する。
- **目的**: 承認待ちの予約だけに集中したい。確定していない予約が承認業務の視界に入らないこと。
- **利用文脈**: 承認待ち一覧（`/approvals`）を定期的に確認し、届いた依頼を処理する。
- **本課題での関心事**:
  - 他人の下書きが承認待ち一覧に現れないこと。
  - 他人の下書きの詳細を開けないこと。
- **可視範囲の変化**: ここが本課題で唯一、既存の権限が狭まる点である。
  現在の `ReservationService.checkReadAccess` は MEMBER のみを本人の予約に限定しており、APPROVER は全予約を閲覧できる。
  本課題では `DRAFT` に限り APPROVER を除外し、403 を返す。
  下書きは承認フローに流れない以上、承認者がその内容を見られる理由がないため。
- **自身の予約について**: 下書きの作成・編集・正式申請は P-01 と完全に同じ振る舞いになる。独立したストーリーは立てない。

## P-03 管理者（`ADMIN`）

- **役割**: リソースの登録・更新、ユーザー管理、全予約の把握。
- **目的**: 予約の全体像を把握する。下書きを含めて、どのリソースにどんな予約の動きがあるかを見る。
- **利用文脈**: 予約一覧（`/reservations`）で全ユーザーの予約を確認する。
- **本課題での関心事**:
  - 他人の下書きも閲覧できること。
  - ただし他人の下書きを勝手に編集したり、代理で正式申請したりはしないこと。
- **可視範囲**: 全予約。`DRAFT` も含む。
- **操作範囲**: 閲覧のみ。
  既存の権限マトリクスで ADMIN には `PUT /api/reservations/{id}` の権限がなく（`ReservationService.update` は申請者本人のみを通す）、
  本課題でもこの制約を維持する。したがって ADMIN は下書きの編集も正式申請もできない。
- **技術的習熟度**: システムの内部構造をある程度理解している。

---

## ペルソナ間の差分

| 観点 | P-01 MEMBER | P-02 APPROVER | P-03 ADMIN |
|---|---|---|---|
| 自分の下書きを作成・編集・正式申請する | 可 | 可（P-01 と同一） | 可（自分の予約について） |
| 他人の下書きの詳細を開く | 403 | 403（本課題で新たに制限される） | 可 |
| 他人の下書きを編集・正式申請する | 403 | 403 | 不可（既存の権限マトリクスどおり） |
| 他人の下書きが承認待ち一覧に現れる | 該当なし | 現れない | 現れない |
| 本課題で独立したストーリーが必要か | 必要 | 必要（可視範囲が狭まるため） | 必要（閲覧可・操作不可の組み合わせ） |
