# User Stories — recurring-reservation

## US-01: 毎週の繰り返し登録

**MEMBER として**、毎週同じ曜日・時刻の予約を、開始日から終了日まで 1 回の操作で登録したい。**それによって** 定例会議のたびに申請する手間をなくせる。

### 受入条件

```gherkin
Scenario: 毎週の繰り返しが、開始日から終了日まで生成される
  Given 2026-11-02（月）10:00 から 11:00 の予約を、recurrenceType が WEEKLY、recurrenceUntil が 2026-11-23 で申請する
  When 予約を作成する
  Then 11/02、11/09、11/16、11/23 の各 10:00 から 11:00 の 4 件が作られる
  And 終了日当日（11/23）の回が含まれる
  And すべて同じ曜日・同じ時刻で、同じ series_id を持つ

Scenario: 終了日の翌日に当たる回は生成されない
  Given 2026-11-02（月）10:00 から 11:00 の予約を、recurrenceType が WEEKLY、recurrenceUntil が 2026-11-22 で申請する
  When 予約を作成する
  Then 11/02、11/09、11/16 の 3 件が作られ、11/23 の回は作られない

Scenario: 日をまたぐ予約も同じ長さで繰り返される
  Given 2026-11-02（月）23:00 から翌 02:00 の予約を、recurrenceType が WEEKLY、recurrenceUntil が 2026-11-09 で申請する
  When 予約を作成する
  Then 11/02 23:00 から 11/03 02:00 と、11/09 23:00 から 11/10 02:00 の 2 件が作られる
  And 各回の長さは 3 時間で、1 回目の endAt から startAt を引いた長さと同じになる

Scenario: レスポンスは startAt の昇順の配列で返る
  Given 上記の WEEKLY の申請が成功する
  When レスポンスを受け取る
  Then 201 で、作られた予約が startAt の昇順の配列として返る
  And 各要素が seriesId・recurrenceType・recurrenceUntil を持つ
```

## US-02: 毎月の繰り返し登録

**MEMBER として**、毎月同じ日の予約を、開始日から終了日まで 1 回の操作で登録したい。**それによって** 月次報告のたびに申請する手間をなくせる。

### 受入条件

```gherkin
Scenario: 毎月同じ日の予約が生成される
  Given 2026-11-15 14:00 から 15:00 の予約を、recurrenceType が MONTHLY、recurrenceUntil が 2027-01-15 で申請する
  When 予約を作成する
  Then 2026-11-15、2026-12-15、2027-01-15 の各 14:00 から 15:00 の 3 件が作られる
  And 終了日当日（2027-01-15）の回が含まれる

Scenario: 存在しない日の月はスキップされる
  Given 2026-01-31 10:00 から 11:00 の予約を、recurrenceType が MONTHLY、recurrenceUntil が 2026-05-31 で申請する
  When 予約を作成する
  Then 01/31、03/31、05/31 の 3 件が作られる
  And 02 月（31 日がない）と 04 月（31 日がない）の回は作られない

Scenario: スキップした月の次は基準日から数える
  Given 2026-01-31 の予約を MONTHLY で申請する
  When 02 月がスキップされる
  Then 次の回は 02/28 でも 03/03 でもなく、03/31 になる
  And 各回は直前の回からの積み上げではなく、1 回目の日（31 日）から数えて決まる

Scenario: 1 回目の日が 28 日以前なら、すべての月が生成される
  Given 2026-01-28 の予約を、recurrenceUntil が 2026-04-28 の MONTHLY で申請する
  When 予約を作成する
  Then 01/28、02/28、03/28、04/28 の 4 件が作られる
```

## US-03: 重複時の全件失敗

**MEMBER として**、繰り返しの中に既存の予約と重なる回があるときは、1 件も登録されずにエラーになってほしい。**それによって** 中途半端に登録された予約を後から片付けずに、条件を直して申請し直せる。

### 受入条件

```gherkin
Scenario: 既存の予約と重なる回が 1 件でもあれば、全件が作られない
  Given 同じリソースに、2026-11-16 10:00 から 11:00 の承認済みの予約がある
  When 2026-11-02（月）10:00 から 11:00 の予約を、WEEKLY で recurrenceUntil 2026-11-23 として申請する
  Then 409 RESERVATION_CONFLICT が返る
  And 11/02、11/09、11/23 の回を含め、予約は 1 件も作られない
  And メッセージは既存の固定文言で、衝突した日付は含まれない

Scenario: 既存の PENDING の予約とも重複として扱われる
  Given 同じリソースに、繰り返しの 1 回分と同じ時間帯の承認待ちの予約がある
  When 繰り返し予約を申請する
  Then 409 RESERVATION_CONFLICT が返り、全件が作られない

Scenario: 生成した予約どうしが重なるときも、全件が作られない
  Given 開始から終了までが 8 日間の予約を、WEEKLY で 2 回分になる終了日で申請する
  When 予約を作成する
  Then 1 回目と 2 回目が互いに重なるため、409 RESERVATION_CONFLICT が返る
  And 既存の予約との重複がなくても、予約は 1 件も作られない

Scenario: 下書きの繰り返しでも、生成した予約どうしの重複は 409 になる
  Given draft が true で、上記と同じ自己重複になる申請をする
  When 予約を作成する
  Then 409 RESERVATION_CONFLICT が返り、予約は 1 件も作られない

Scenario: 承認者がいないときも全件がロールバックされる
  Given 承認が必要なリソースで、APPROVER ロールのユーザーが 1 人もいない
  When 繰り返し予約を申請する
  Then 422 APPROVER_NOT_AVAILABLE が返り、予約も承認ステップも 1 件も作られない

Scenario: 重なる回のないときは、境界が接する予約と並んでも登録できる
  Given 既存の予約が 09:00 から 10:00 で、繰り返しの各回が 10:00 から 11:00 である
  When 繰り返し予約を申請する
  Then 境界が接するだけなので重複とは扱われず、全件が作られる
```

## US-04: 繰り返し指定の検証と従来互換

**MEMBER として**、繰り返しを使わない申請は従来どおり 1 件で登録され、不正な繰り返し指定ははっきりしたエラーになってほしい。**それによって** 既存の使い方を変えずに済み、入力の誤りにも気づける。

### 受入条件

```gherkin
Scenario: 「繰り返さない」は従来どおり 1 件で登録される
  Given recurrenceType を指定しない、または NONE で申請する
  When 予約を作成する
  Then 1 件の予約が作られ、レスポンスは 1 件の配列（201）になる
  And series_id と recurrence_until は NULL で、recurrence_type は NONE になる

Scenario: NONE で終了日を指定すると 400 になる
  Given recurrenceType が NONE で、recurrenceUntil が指定されている
  When 予約を作成する
  Then 400 VALIDATION_ERROR が返り、予約は作られない

Scenario: WEEKLY または MONTHLY で終了日が未指定だと 400 になる
  Given recurrenceType が WEEKLY（または MONTHLY）で、recurrenceUntil が指定されていない
  When 予約を作成する
  Then 400 VALIDATION_ERROR が返り、予約は作られない

Scenario: 終了日が開始日より前だと 400 になる
  Given startAt の日付が 2026-11-02 で、recurrenceUntil が 2026-11-01 である
  When 予約を作成する
  Then 400 VALIDATION_ERROR が返り、予約は作られない
  And 既存の endAt が startAt 以前のときの 422 とは、ステータスが異なる

Scenario: 終了日が開始日と同じ日なら、1 件だけ作られる
  Given startAt の日付と recurrenceUntil がどちらも 2026-11-02 で、recurrenceType が WEEKLY である
  When 予約を作成する
  Then 1 件の予約が作られ、レスポンスは 1 件の配列になる

Scenario: 終了日は開始日から 2 年後の同じ日まで指定できる
  Given recurrenceType が WEEKLY で、recurrenceUntil が開始日のちょうど 2 年後である
  When 予約を作成する
  Then 件数による拒否はなく、重複がなければ 105 件（開始日が月曜の場合）が作られる

Scenario: 終了日が開始日から 2 年を超えると 400 になる
  Given recurrenceType が WEEKLY で、recurrenceUntil が開始日の 2 年後の翌日である
  When 予約を作成する
  Then 400 VALIDATION_ERROR が返り、予約は作られない
  And フォームも、送信前に「繰り返し終了日は開始日から 2 年以内にしてください」を表示して止める
  And 開始日が 2 月 29 日で 2 年後が平年なら、上限は 2 月 28 日になる
```

## US-05: 下書き・承認が必要なリソースとの併用

**MEMBER として**、繰り返し予約を下書きとして保存したり、承認が必要なリソースで申請したりしたい。**それによって** 通常の予約と同じ流れで繰り返し予約を扱える。**APPROVER として**、繰り返しの各回を 1 件ずつ承認・却下したい。**それによって** 回ごとに判断できる。

### 受入条件

```gherkin
Scenario: 下書きの繰り返しは、全件が DRAFT で作られる
  Given draft が true で、WEEKLY の繰り返しを申請する
  When 予約を作成する
  Then 全件が DRAFT で作られ、承認ステップは作られない
  And 全件が同じ series_id を持つ

Scenario: 下書きの各回は、個別に正式申請できる
  Given 繰り返しの下書きが 4 件ある
  When ある回だけ、既存の更新 API で submit を true にして正式申請する
  Then その回だけが PENDING（承認不要のリソースなら APPROVED）になり、ほかの回は DRAFT のままである

Scenario: 承認が必要なリソースでは、全件が PENDING で作られ、承認ステップも件数分できる
  Given 承認が必要なリソースで、4 回分の繰り返しを申請する
  When 予約を作成する
  Then 4 件が PENDING で作られ、承認ステップが 4 件作られる

Scenario: 承認が不要なリソースでは、全件が APPROVED で作られる
  Given 承認が不要なリソースで、4 回分の繰り返しを申請する
  When 予約を作成する
  Then 4 件が APPROVED で作られ、承認ステップは作られない

Scenario: APPROVER は繰り返しの各回を 1 件ずつ承認・却下できる
  Given 承認が必要なリソースの繰り返し予約 4 件が PENDING である
  When APPROVER が 1 件を承認し、別の 1 件を却下する
  Then 承認した回だけが APPROVED、却下した回だけが REJECTED になり、残りの 2 件は PENDING のままである
  And まとめて承認する操作は提供されない
```

## US-06: 個別の予約としての管理

**MEMBER として**、繰り返しで登録した予約を、1 回ごとの独立した予約として扱いたい。**それによって** 都合の悪い回だけをキャンセルしたり変更したりできる。

### 受入条件

```gherkin
Scenario: 繰り返しで登録した予約は、予約一覧に個別に表示される
  Given WEEKLY の繰り返しで 4 件の予約を登録した
  When 予約一覧を開く
  Then 4 件が別々の行として表示される
  And 一覧にはシリーズに関する列や表示を追加しない

Scenario: 1 件だけキャンセルできる
  Given 同じ series_id を持つ予約が 4 件ある
  When そのうち 1 件をキャンセルする
  Then その予約だけが CANCELLED になり、ほかの 3 件は変わらない

Scenario: 1 件だけ変更できる
  Given 同じ series_id を持つ PENDING の予約が 4 件ある
  When そのうち 1 件の日時を既存の更新 API で変更する
  Then その予約だけが変更され、ほかの 3 件は変わらない
  And 変更した予約の series_id は変わらない

Scenario: シリーズの一括変更・一括キャンセルは提供されない
  When 繰り返しで登録した予約の画面・API を確認する
  Then シリーズ全体を一度に変更・キャンセルする操作は存在しない
```

## US-07: フォームでの繰り返し入力と登録結果

**MEMBER として**、予約申請フォームで繰り返しの種別と終了日を選び、登録の結果をすぐに知りたい。**それによって** 迷わず入力でき、何件登録されたかが分かる。

### 受入条件

```gherkin
Scenario: 「繰り返さない」が初期値で、終了日の入力欄は表示されない
  Given 予約申請フォーム（/reservations/new）を開く
  Then 繰り返しの選択は「繰り返さない」になっている
  And 終了日の入力欄は表示されない

Scenario: 「毎週」または「毎月」を選ぶと、終了日の入力欄が現れて必須になる
  Given 予約申請フォームを開いている
  When 繰り返しで「毎週」を選ぶ
  Then 終了日の入力欄（日付）が現れる
  And 終了日が未入力のまま送信しようとすると、フォームがエラーを表示し、送信されない

Scenario: 「繰り返さない」に戻すと、終了日は送信されない
  Given 「毎週」を選び、終了日を入力した
  When 「繰り返さない」に戻して送信する
  Then 終了日は API に送られず、1 件の予約として登録される

Scenario: 登録に成功するとトーストが表示され、予約一覧へ遷移する
  Given 4 回分の繰り返しを入力して「予約を申請する」を押す
  When 登録が成功する
  Then 「4 件の予約を登録しました」というトーストが表示される
  And /reservations へ遷移する

Scenario: 下書き保存で成功すると、下書きの一覧へ遷移する
  Given 繰り返しを入力して「下書き保存」を押す
  When 登録が成功する
  Then トーストが表示され、/reservations?status=DRAFT へ遷移する

Scenario: 重複のエラーがフォームに表示される
  Given 繰り返しの中に既存の予約と重なる回がある
  When 「予約を申請する」を押す
  Then 409 RESERVATION_CONFLICT の固定文言がフォーム下部に表示される
  And 入力内容は保持され、条件を直して再送信できる

Scenario: 1 件の登録でも、件数付きのトーストになる
  Given 「繰り返さない」で申請する
  When 登録が成功する
  Then 「1 件の予約を登録しました」とトーストが表示される
```

## US-08: 詳細画面のシリーズ情報

**MEMBER として**、繰り返しで登録した予約の詳細画面で、シリーズの情報を見たい。**それによって** その予約が何件中のどこにあたり、あと何回残っているかが分かる。

### 受入条件

```gherkin
Scenario: 繰り返しで作った予約の詳細に、シリーズの情報が表示される
  Given 2026-11-02 から毎週 4 回（11/02、11/09、11/16、11/23）の予約を登録した
  When 2 回目（11/09）の予約の詳細画面を開く
  Then 繰り返しの種別（毎週）と終了日が表示される
  And シリーズ件数が 4 件と表示される
  And 残り回数が 2 回（11/16 と 11/23）と表示される

Scenario: 残り回数は、表示中の予約より後の件数で、自身を含まない
  Given 4 件のシリーズがある
  When 最後の回の詳細画面を開く
  Then 残り回数は 0 回と表示される
  And 閲覧する日が変わっても、残り回数は変わらない

Scenario: シリーズ件数と残り回数は、キャンセル済み・却下済みも数える
  Given 4 件のシリーズのうち、3 回目をキャンセル済みにした
  When 2 回目の詳細画面を開く
  Then シリーズ件数は 4 件、残り回数は 2 回と表示される

Scenario: 詳細 API だけがシリーズ件数と残り回数を返す
  When 繰り返しで作った予約を GET /api/reservations/{id} で取得する
  Then レスポンスに seriesId・recurrenceType・recurrenceUntil・シリーズ件数・残り回数が含まれる
  And 予約一覧の API は、シリーズ件数と残り回数を計算せず返さない

Scenario: 「繰り返さない」の予約には、シリーズの欄が表示されない
  Given recurrenceType が NONE の予約がある
  When 詳細画面を開く
  Then シリーズに関する欄は表示されない
  And API のレスポンスでは、シリーズ件数と残り回数は null になる

Scenario: 予約の一覧画面には、シリーズ情報が表示されない
  Given 繰り返しで作った予約がある
  When 予約一覧を開く
  Then 繰り返しの種別・シリーズ件数・残り回数は一覧に表示されない
```

## 要件・受入条件との対応

| 要件の受入条件（requirements.md） | ストーリー |
|---|---|
| 「毎週」で、同じ曜日・時刻の予約が一括登録される | US-01 |
| 「毎月」で、毎月同日の予約が一括登録される | US-02 |
| 一括登録された予約が一覧に個別に表示され、詳細確認・キャンセルができる | US-06 |
| 重複があれば全件が登録されず、エラーメッセージが表示される | US-03、US-07 |
| 生成した予約どうしが重なる場合も 409 になる | US-03 |
| 「繰り返さない」（初期値）は従来どおり 1 件 | US-04、US-07 |
| 400 の 3 パターン | US-04 |
| 下書き保存との併用 | US-05 |
| 承認が必要なリソースで N 件の承認ステップ | US-05 |
| 日をまたぐ予約の繰り返し | US-01 |
| 詳細画面に種別・終了日・シリーズ件数・残り回数、一覧には出ない | US-08、US-06 |
| 登録成功のトースト | US-07 |
| V003 が正常に実行され、既存データへの影響がない | 非機能要件（PostgreSQL での確認）。US-04 の「従来互換」が既存データの挙動に対応 |
| 既存テストが pass する | 非機能要件（配列化への追従後） |
| 繰り返し日の生成ロジックのユニットテスト | US-01、US-02、US-03 のシナリオがテスト項目に対応 |
