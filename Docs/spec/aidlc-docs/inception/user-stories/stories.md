# User Stories: CSV 帳票出力（Issue #29）

- **入力**: `Docs/spec/aidlc-docs/inception/requirements/requirements.md`（承認済み）、`Docs/spec/aidlc-docs/inception/plans/story-generation-plan.md`（承認済み）
- **分割方式**: Feature-Based（計画 Q2）
- **受入条件の書式**: Given / When / Then（計画 Q3）
- **ペルソナ**: `personas.md` の P1 ADMIN（主）、P2 MEMBER、P3 APPROVER（使えないことを確認する対象）

画面上の入力 UI（期間・ステータスの入力欄の形、既存のステータスタブとの連動）とダウンロード経路は Application Design で決めるため、受入条件では「ADMIN が条件を指定して CSV をダウンロードする」とだけ書き、操作手順の細部は規定しない。

---

## US-1 全件の予約を CSV でダウンロードする

**管理者（ADMIN）として、予約一覧を CSV ファイルでダウンロードしたい。それは、Excel で開いて社内報告や集計に使うためだ。**

- **要件**: RPT-01、RPT-02、RPT-05
- **ペルソナ**: P1

### 受入条件

**AC-1.1 ボタンからダウンロードできる**
- Given ADMIN でサインインし、予約一覧画面（`/reservations`）を開いている
- When 期間もステータスも指定せずに「CSV ダウンロード」ボタンを押す
- Then ブラウザに CSV ファイルがダウンロードされる
- And API の応答は `Content-Type: text/csv` である

**AC-1.2 文字コードとヘッダ行**
- Given AC-1.1 でダウンロードした CSV がある
- When ファイルの中身を確認する
- Then 文字コードは UTF-8 で、先頭に BOM が付いている
- And 1 行目は「予約ID,リソース名,申請者名,開始日時,終了日時,目的,承認状態」の日本語ヘッダ行である

**AC-1.3 対象と並び順**
- Given 複数のユーザーが申請した、さまざまなステータスの予約が登録されている
- When ADMIN が条件を指定せずに CSV をダウンロードする
- Then 全ユーザー・全ステータスの予約が 1 件 1 行で出力される
- And 行は開始日時の昇順に並ぶ

**AC-1.4 値の表記**
- Given 開始日時が 2026-06-02T10:00:00、ステータスが `PENDING` の予約がある
- When ADMIN が CSV をダウンロードする
- Then その行の開始日時は `2026/06/02 10:00`（ゼロ埋め、秒なし）で出力される
- And 承認状態は画面と同じ日本語表示名「承認待ち」で出力される（他のステータスも ドラフト / 承認済み / 却下 / キャンセル済み の表示名）

**AC-1.5 カンマや改行を含む値**
- Given 目的に「定例会議, 資料 "A" 確認」のようにカンマとダブルクォートを含む予約、または改行を含む予約がある
- When ADMIN が CSV をダウンロードする
- Then その値はダブルクォートで囲まれ、値の中のダブルクォートは二重にして出力される（要件の仮定 A3、RFC 4180）
- And Excel で開いたときに列がずれない

**AC-1.6 該当 0 件**
- Given 予約が 1 件も登録されていない（または条件に合う予約がない）
- When ADMIN が CSV をダウンロードする
- Then 応答は 200 で、ヘッダ行だけの CSV がダウンロードされる

## US-2 期間で絞り込んで CSV をダウンロードする

**管理者（ADMIN）として、期間を指定して予約を CSV で取り出したい。それは、月次報告などで必要な範囲だけを扱うためだ。**

- **要件**: RPT-03（期間）
- **ペルソナ**: P1

### 受入条件

**AC-2.1 開始日時で判定する**
- Given 開始日時がそれぞれ 2026-05-31T23:00:00、2026-06-01T00:00:00、2026-06-30T23:00:00、2026-07-01T00:00:00 の予約がある
- When ADMIN が `from=2026-06-01T00:00:00`、`to=2026-07-01T00:00:00` を指定して CSV をダウンロードする
- Then 2026-06-01T00:00:00 と 2026-06-30T23:00:00 に始まる予約だけが出力される（`from` は含み、`to` は含まない）

**AC-2.2 期間の前から続く予約は含めない**
- Given 2026-05-31T22:00:00 に始まり 2026-06-01T02:00:00 に終わる予約がある
- When ADMIN が AC-2.1 と同じ期間を指定して CSV をダウンロードする
- Then その予約は出力されない（終了日時は判定に使わない）

**AC-2.3 片方だけの指定はエラー**
- Given ADMIN でサインインしている
- When `from` だけ、または `to` だけを指定して API を呼ぶ
- Then 応答は 400 で、`code` は `VALIDATION_ERROR` である

**AC-2.4 from ≧ to はエラー**
- Given ADMIN でサインインしている
- When `from` に `to` と同じ日時、または `to` より後の日時を指定して API を呼ぶ
- Then 応答は 400 で、`code` は `VALIDATION_ERROR` である

**AC-2.5 オフセット付きの日時はエラー**
- Given ADMIN でサインインしている
- When `from=2026-06-01T00:00:00+09:00` のようにオフセット付きの日時を指定して API を呼ぶ
- Then 応答は 400 で、`code` は `VALIDATION_ERROR` である（要件の仮定 A2、`api-spec.md` §日時フォーマット）

## US-3 ステータスで絞り込んで CSV をダウンロードする

**管理者（ADMIN）として、承認状態を指定して予約を CSV で取り出したい。それは、承認済みの利用実績だけ、承認待ちの案件だけ、のように目的に合うデータを扱うためだ。**

- **要件**: RPT-03（ステータス）
- **ペルソナ**: P1

### 受入条件

**AC-3.1 1 つのステータスで絞り込む**
- Given `PENDING`、`APPROVED`、`REJECTED`、`CANCELLED` の予約がそれぞれある
- When ADMIN が `status=APPROVED` を指定して CSV をダウンロードする
- Then 承認状態が「承認済み」の予約だけが出力される

**AC-3.2 複数のステータスで絞り込む**
- Given AC-3.1 と同じ予約がある
- When ADMIN が `status=PENDING&status=APPROVED` を指定して CSV をダウンロードする
- Then 「承認待ち」と「承認済み」の予約だけが出力される（要件の仮定 A1、既存の `GET /api/reservations` と同じ指定方法）

**AC-3.3 期間と組み合わせる**
- Given 期間内外に、さまざまなステータスの予約がある
- When ADMIN が期間とステータスを両方指定して CSV をダウンロードする
- Then 期間の条件とステータスの条件の両方を満たす予約だけが出力される

## US-4 ADMIN 以外は CSV 出力を使えない

**システムとして、ADMIN 以外のロールには CSV 帳票出力を使わせない。それは、全ユーザーの予約（他人の申請者名や利用目的を含む）が持ち出されないようにするためだ。**

- **要件**: RPT-04、RPT-05（表示は ADMIN のみ）
- **ペルソナ**: P2、P3（対照として P1）

### 受入条件

**AC-4.1 MEMBER と APPROVER にはボタンが表示されない**
- Given MEMBER または APPROVER でサインインしている
- When 予約一覧画面（`/reservations`）を開く
- Then CSV ダウンロードの UI は表示されない
- And それ以外の画面表示（自分の予約一覧、ステータスタブ）は従来と変わらない

**AC-4.2 MEMBER が API を呼ぶと 403**
- Given MEMBER でサインインしている
- When `GET /api/reports/reservations/csv` を直接呼ぶ
- Then 応答は 403 である

**AC-4.3 APPROVER が API を呼ぶと 403**
- Given APPROVER でサインインしている
- When `GET /api/reports/reservations/csv` を直接呼ぶ
- Then 応答は 403 である

**AC-4.4 未認証は 401**
- Given 認証トークンを付けていない
- When `GET /api/reports/reservations/csv` を呼ぶ
- Then 応答は 401 である

## INVEST の点検

| ストーリー | Independent | Negotiable | Valuable | Estimable | Small | Testable |
|---|---|---|---|---|---|---|
| US-1 | 単独で価値が出る（絞り込みなしでも報告に使える） | 実装方式は Application Design に委ねている | ADMIN が CSV を得られる | エンドポイント、CSV 生成、ボタンの範囲で見積もれる | 6 条件。本課題で最大だが分割すると単独価値が薄れる | 全条件が具体値で検証できる |
| US-2 | US-1 のエンドポイントに条件を足す形で依存する。US-3 とは独立 | 入力 UI の形は未規定 | 必要な期間だけを取り出せる | クエリ条件と検証の追加 | 5 条件 | 境界値（`from` 含む / `to` 含まない）まで具体化 |
| US-3 | US-1 に依存、US-2 とは独立（AC-3.3 のみ両方を使う） | 入力 UI の形は未規定 | 目的に合う状態だけを取り出せる | 既存一覧と同じ指定方法で見積もりやすい | 3 条件 | 具体的なステータスで検証できる |
| US-4 | US-1 の機能を前提とするが、検証は独立して行える | 非表示の方法は未規定 | 予約データの持ち出しを防ぐ | 既存の `@PreAuthorize` と同じ方式 | 4 条件 | ロールごとの応答コードで検証できる |

**点検の結果**: US-2〜4 は US-1（エンドポイントと CSV 生成）を土台にするため、Independent は完全には満たさない。期間・ステータス・アクセス制限は、いずれも同じエンドポイントの振る舞いなので、US-1 なしでは成り立たない。そのため依存を許容し、実装順を US-1 を先頭にすることで扱う（順序は Workflow Planning で決める）。その他の観点は満たしている。
